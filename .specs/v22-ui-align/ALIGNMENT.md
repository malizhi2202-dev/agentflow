## 2. 结论（必须先说清的一句）

这不是「几处样式没调」：**壳层与页面骨架没有按原型建**（无 `.app-top`、无语义组件层、页头三套写法），
所以 127 页原型 × 41 页实现的落差里，**界面落差是结构性的**，靠逐页补内联样式会继续发散。

正确顺序：**先建壳层与组件层（一次），再逐页把页面装进去**——否则每改一页都会再发明一套页头。

## 4. 风险

- 内联样式 2669 处是历史欠账：W1 若强推「全改类名」，diff 会很大且易回归 → W1 只**新增**壳层与组件，页面逐步迁移，不做全仓替换。
- 原型 `.chip/.tbl` 依赖 `assets/base.css`（在 `.specs/` 内部）；平台前端不能直接引原型 CSS（两套 token 会打架）→ W1 需把**用到的**规则搬成平台组件（不复制整份 base.css）。
- 侧栏分组已与原型不一致（见 §1），先定口径再动 W2，否则 W2 返工。
