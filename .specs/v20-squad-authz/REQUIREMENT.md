# REQUIREMENT: 小队写操作授权

- **Change ID**: v20-squad-authz
- **上游**: `CHANGE.md`（G1 4/4）
- **上下文源**: `CLAUDE.md`

## 用户故事

1. **作为小队的创建者**，我希望能给自己建的队加人、移人、归档、指派任务，不需要找管理员。
2. **作为平台管理员**，我希望能管理任何小队（处理离职、误建、事故）。
3. **作为普通成员**，我不该能改别人建的小队——被拒绝时我要看到明确原因，而不是"悄悄成功"。

## 验收准则（AC）

### AC-1 · creator 可写
`created_by == 当前用户` 时，加成员 / 移成员 / 归档 / 指派任务全部允许。
**验证**：服务层用例（4 个动作各一条）+ 路由级 200。

### AC-2 · 平台管理员可写
`role == admin` 时，即使不是 creator 也允许全部写操作。
**验证**：服务层用例 + 路由级 200。

### AC-3 · 其他人被拒绝（403 + 明确文案）
既非 creator 也非平台管理员 → **403**，文案写明「只有小队创建者或平台管理员可以修改该小队」。
**验证**：服务层用例断言异常类型与文案；路由级断言 403 与 `detail`。

### AC-4 · 读不被影响
`GET /api/squads` 与 `GET /api/squads/{ref}` 对任何登录用户仍可读（列表本就是组织公开信息）。
**验证**：路由级用例（普通成员 200）。

### AC-5 · 无回归
后端全量 `unittest discover` 与登记基线同红（29F/12E/6S），**0 新增红**；`test_teams` 全绿。
**验证**：全量输出贴入 TEST.md。

## 范围切分

### v1（本次必做）
AC-1…AC-5。

### v2（下一轮考虑）
- 小队"我创建的"筛选（前端）。
- `created_by` 为空的历史小队 backfill。

### out（永远不做）
- 小队成员级细粒度权限（口径就是 creator/admin）。
- 小队 owner 转让（模型无该字段）。

## 非功能性需求

- **安全**：判定在服务层（唯一真源），路由只映射状态码；403 文案不泄漏额外内幕。
- **可观测**：拒绝路径不写审计（与既有 403 一致）；如后续要审计再加。
- **兼容**：不改响应形状；不新增依赖；无迁移。

## 依赖与假设

- 依赖：波 4 的 `squad.created_by` 字段（已存在）。
- 假设：现存小队都由某个登录用户创建（`created_by` 非空）；为空的按"只有管理员可改"处理（从严）。
