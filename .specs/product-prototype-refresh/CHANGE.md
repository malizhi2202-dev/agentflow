## Why（为什么做）

1. **产品没有一份独立的原型事实源**：仓库内（main 与全部分支）不存在 `product-design.html` 或任何原型文档——界面设计隐含在 32 个页面代码里，产品能力描述只有 README.md。没有可评审、可对照、可挂竞品结论的"产品原型 + 界面原型"层。
2. **既有文档与代码已严重漂移**：`.specs/README-CONSISTENCY-REPORT.md`（2026-07-06）实测 README 10 项数据 8 项不准（准确率 20%）；`.specs/CONTEXT.md` 证实代码持续增长而文档未动（页面 20→32、服务 20→25、路由 24→27、组件 25→28，新增控制面/域管理/告警/LLM 提供商等模块 README 均未记载）。融合竞品结论前必须先校准事实底稿，否则新结论贴在过时画面上。
3. **产品能力矩阵缺外部参照**：AgentFlow 定位「通用 Agent 编排与管控平台」（`CLAUDE.md`），相对同类产品（issue 点名 Multica、Buzzz、OpenWorker、AgentOS 等）能力是否完整，从未做过系统比对；需求方明确要求调研并找出可补充进本项目的能力缺口。

## What（做什么）

三个工作包，全部落在文档 / 原型层，串行推进（W3 以 W1/W2 产物为输入），与 issue 三步诉求一一对应：

- **W1 现状审核**：以 `README.md`、`.specs/CONTEXT.md`、一致性报告为文档侧输入，以 `frontend/src/pages`（34 个 .tsx 文件 / **32 个实际挂载路由页**——页面清单口径一律以 `App.tsx` 挂载集为准；文件数与挂载数差 2：`SecurityPage.tsx`、`AssemblyView.tsx` 全仓无引用，W1 登记「死代码还是待接入」定性【待确认】）、`components`（28，2026-09-22 复测未变）、`stores`（11）、`backend/routes`（2026-09-22 复测：29 个 .py 文件 / 168 个行锚定端点；快照口径 27 模块 / 153 端点的差异系 regex 锚定与 `__init__` 取舍不同所致——W1 定单一计数口径并写入底稿）为代码侧事实源，产出「产品能力现状事实底稿 + 文档漂移差异清单 + 孤儿页面/无引用组件盘点」。
- **W2 竞品调研（本 change 只锁定清单与口径，逐项深挖归 1-requirement）**：至少覆盖 Multica、Buzzz、OpenWorker、AgentOS 四个产品（"等"的扩展候选需先列清单经人工确认），统一口径产出能力缺口清单，每条含【来源 URL】【能力描述】【适配初判：值得引入 / 观望 / 不适配 + 理由】。
- **W3 融合产出原型**：一份产品原型 + 界面原型文档（默认 `product-design.html`，零外部依赖、浏览器直开——已升格为验收线 4 的硬判据，见 G1 🔴 R-2；落 `.specs/product-prototype-refresh/`；若人工提供既有稿则按其位置融合）。在 W1 事实底稿之上呈现全部能力域与界面原型，并叠加竞品结论；每条新增带双字段标注：「来源 = 审核发现 N / 调研结论 N」+「**归属** = 本项目已有（须能在 `frontend/src/pages` 或 `backend/routes` 指到锚点）/ 本项目缺失-竞品建议新增」（G1 🔴：防把竞品宣传文案当成本项目既有能力）。

## 视觉调性（前端项目必填）

- **选定**：以既有前端实现为基线——Tremor 3.18 + Tailwind 3.4 + `src/styles/tokens.css` 的管控台式（深色、信息密度优先）调性。
- **理由**：诉求是「融合进既有产品 / 界面原型」，界面原型应贴近真实实现的呈现以便评审对照，而非另起一套新皮肤（步骤 0.6 强偏好例外：不重选，直接锁定既有体系）。
- **参考产品**：第一参照 = 本项目运行界面（`frontend/` 实际页面）；外部密度/层级参照 Linear、Vercel、Grafana 类管控台。
- **明确排除**：高饱和营销落地页调性（管控平台非售卖页）；C 端沉浸式/大留白调性（无大众终端用户场景）。
- ⚠️ `code-kit/reference/ui-aesthetics.md` 九卡库在本仓库未安装（HEAD 即「去掉code-kit标识」），本字段未按卡片编号预选；若人工选择"新建原型"并想要新调性，在 2a 提出后修正。若人工提供 `product-design.html` 既有稿，以该稿调性为准。

## 验收线（粗粒度，不是 AC）

1. 存在一份可浏览器直开的产品原型 + 界面原型文档，覆盖平台全部能力域——清单以 README 功能模块为基线、经 `App.tsx` 挂载页对照补齐，共 **11 域**：工作流监控 / Agent 编排 / 控制面与域管理 / 对话中心 / 工具库与模板市场 / 项目管理 / 角色系统 / 安全与审计 / **知识产物与文档**（DocEditor、SpecsEditor、OrchDocPage、KnowledgeBase、Artifact 页；`CLAUDE.md` 定位核心能力，且有「知识产物是产品的一等数据」约定）/ **告警**（AlertsPage）/ **人工审批**（ApprovalPage）——后三域 README 功能模块层未记载，系 G1 🟫 票补入；界面原型能呈现 **W1 实测的全部挂载路由页**（2026-09-22 复测 = 32；快照数字仅参考，见「数字口径」条）的信息架构骨架并含调研新增界面。
2. 竞品调研产物覆盖至少 4 个点名产品、每条结论带来源引用；能力缺口清单逐条有去向：已融入原型 / 登记议题（需代码）/ 否决（带理由），零「写了没落」。（本条判定发生在 1-requirement 出口——0-change 只锁定清单与口径，见 W2）
3. 原型文档与代码自洽：文中引用的模块与页面清单可在仓库中找到对应实现，可抽查验证。交付的原型文档头部须声明**校准基线**（对应 commit SHA + 日期 + 校准时点的能力域/页面清单快照），使后续 S-align 能判定其是否过期——该文档按议题 `docs-drift-resync` 安排将成为产品事实源，不得自身变成下一份漂移稿。
4. **原型 HTML 零外部依赖**（G1 🔴 R-2；「零外部依赖」原只在 W3 括号内，现升格为可 grep 判据）：无 `<script src=`、无 `<link … href="http`、无 `@import url(`、无 CDN 域名；图表/样式全部内联，颜色与间距取自 `frontend/src/styles/tokens.css` 实际值；断网环境双击可完整渲染。核对方式：上述 grep 模式对该 HTML 全 0 命中 + 断网打开截图。这是供应链闸口——CDN `<script>` 等于绕过 `package.json` 偷偷新增第三方依赖，依赖审计完全看不见它。
