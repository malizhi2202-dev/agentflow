# ADR-003: 交付稿的标签模型 = 归属四值 × 标注三态，两轴正交、值域闭集、分属性承载

- **状态**: accepted（2026-09-22，`product-prototype-refresh` 2-design；待 G2 方案门票面确认）
- **关联**: `@.specs/product-prototype-refresh/DESIGN.md` §1.5 / D4 / D6 / §3 组合矩阵 · `@.specs/CONTEXT.md` §15.1（「归属四值」「标注三态」两条术语）· `@.specs/product-prototype-refresh/REQUIREMENT.md` AC-5 / AC-11 / AC-13（含 `:120` 注脚）· `@.specs/product-prototype-refresh/BASELINE-code-facts.md` §3/§4
- **决策者**: Architect + G2 方案门专家团

## Context

交付稿要在同一份界面里回答两个**互相独立**的问题：

| 轴 | 回答的问题 | 取值（已锁术语） | 由谁验收 |
|---|---|---|---|
| **归属** | 这项能力**是不是我们的现状** | `本项目已有` / `部分已有`（半成品，须点明缺哪半条腿）/ `缺失-竞品建议新增` / `缺失` | AC-5（锚点 + 禁同行堆叠） |
| **标注** | 这项能力**在界面/演示里算什么** | `未接入` / `演示边界` / `规划中` | AC-11（六处逐处）＋ AC-13（9 条融入逐块） |

三条来自票面的教训逼出这条 ADR：

- AC-13 注脚（`REQUIREMENT.md:120`）明写：15 条缺口里归属为"缺失-竞品建议新增"仅 7 条、"部分已有"6 条、"本项目已有"1 条、"缺失"1 条 —— **按归属定阈值会定出永远达不到的数**；"归属只管是不是我们的现状，本条（AC-13）管调研结论进没进界面"。
- G1 🔴 的假锚点教训：一条"本项目已有"没有仓库锚点，就是幻觉（→ `data-anchor` 必填 + K2 `[ -f ]` 逐条证伪）。
- 触发本次设计的那条评论第 4 条：两条轴**已经被 §15.1 拆成两个术语，写稿时不能再合并**（实测最易塌缩成自由文本"部分可用"）。

## Decision

1. 两轴在交付稿里**分别用两个属性承载，禁止合并成一个词或一列**：
   - `data-owner="本项目已有|部分已有|缺失-竞品建议新增|缺失"`
   - `data-state="未接入|演示边界|规划中"`（不标注 = 该属性不出现，禁写"已接入/正常"这类反向自证词）
2. **值域闭集**（K3）：两属性的取值集合各按 §15.1 术语穷举，任何第四个值（如"基本可用""大致支持"）即判红。术语新增/改名只能走 `CONTEXT.md` §15.1，不在交付稿里造词。
3. **合法组合矩阵**（DESIGN §3）固化两轴的语义，抽查即按它判：
   - `本项目已有 × 未接入` ✗（既有能力不得画成没接，属实则改判归属）
   - `缺失* × 演示边界` ✗（把竞品能力画成"我们的演示边界"= 最严重的一类失真）
   - `缺失-竞品建议新增 × 未接入` ✗（`未接入` 语义前提是"我们有码没接线"；本轮探针正是这条被判出违规）
   - `部分已有 × 未接入/演示边界` ✓（六处待标注里的四处壳能力属此）
   - `缺失* × 规划中` ✓（须同时带 `data-slug`，与 RESEARCH §2 现算集对账）
4. **一条记录一个块**（D6）：归属与标注随条目**独占一行/一块**，配"出现次数 == 行数"的堆叠探测；禁把 9 个编号挤在一行交差。
5. **枚举字面串在一条记录里只出现一次**（D13）：值只写在 `data-owner` / `data-state` 属性里，可见徽标文案由 CSS `::after` 配语义 class 提供、**CSS 里不重抄枚举值**。否则 AC-5 的堆叠探测会在**完全合规**的稿子上假红（实测双写形态 32 行合格骨架 `occ=64 / lines=32`；单写形态 `32/32` 通过）。
6. **两轴同行配对**（K3b）：判定非法组合时按**同一行**取 `data-owner` 与 `data-state` 配对（跨标签属性选择器会漏配，本轮已实测：反例稿的非法组合 `缺失-竞品建议新增|未接入` 只有在行内配对形态下才报得出）。
5. **交付稿不进内部弱点清单**：`部分已有` 只写 BASELINE §4 S1-S10 里**允许写入原型的措辞列**（限定式），不搬整表（DESIGN §9.5）。

## Consequences

**正向**

- AC-5（真锚点）、AC-11（六处逐处）、AC-13（九条融入逐块）三条判据各自有独立抓手，互不顶包：一份"把 9 条竞品结论全漏画"的稿，过去能在其余 12 条 AC 上全绿（AC-13 ③ 原话），现被 K4/K9 的集合 diff 拦住。
- "竞品说的"与"我们有的"在界面上物理分离（`data-from` + `data-owner` 同时必填），直接满足 US-4"读者能区分竞品说法与本项目现状"。
- 组合矩阵把"看起来合理其实失真"的写法（把缺失写成未接入、把竞品能力写成演示边界）变成可判定的违规，而不是靠评审眼力。

**负向 / 代价**

- 写稿更啰嗦：每个条目要同时决定两件事并各写一个属性，且两轴不可省略其一。
- 语义判定的责任前移到写稿者（矩阵里 `△` 那两格需要判断），5-test 必须按 UAT-6/UAT-7 逐处勾，不能只看计数地板 —— 这是刻意保留的人工环节。
- 若日后要加第三轴（如"优先级/成熟度"），**不得复用这两个属性名**，须先在 §15.1 立术语再开属性，否则闭集闸会误伤。

**推翻本 ADR 的代价**：高。合并两轴 = 同时让 AC-5、AC-11、AC-13 的判据互相顶包（AC-13 注脚已给出反例路径），要改就得回到 1-requirement 重写三条 AC 并重开需求门票面。
