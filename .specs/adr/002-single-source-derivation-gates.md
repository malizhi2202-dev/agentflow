# ADR-002: 文档型交付物的数字与清单一律「单处真源 + 派生 diff」，禁手抄、禁第二工具

- **状态**: accepted（2026-09-22，`product-prototype-refresh` 2-design；待 G2 方案门票面确认）
- **关联**: `@.specs/product-prototype-refresh/DESIGN.md` §1.5 / D2 / D6 / D9 / D10 / §5-R2 R3 R9 · `@.specs/product-prototype-refresh/BASELINE-code-facts.md` §1/§2/§4 · `@.specs/product-prototype-refresh/RESEARCH-competitors.md` §2「计数不变式」 · `@.specs/CONTEXT.md` §15.2 已锁决策（唯一真源 = 反引号 slug 去重集）
- **决策者**: Architect + G2 方案门专家团（G2 🟩 的"单处真源 + 两处 diff"修法在此被推广为通用纪律）

## Context

本 change 的 13 条 AC 有 9 条是对交付稿跑的文本命令。已实测出三类**假绿/假红**通道：

1. **窗口漂移**：`awk '/安全与审计/{f=1} f{print} f&&/<\/section>/{f=0}'` 以中文措辞为起点。把该措辞写进侧边栏后，窗口起点漂到导航，**安全段漏写边界句仍判 1**；同稿换成节点锚定 `awk '/<section id="sec-security">/{f=1}…'` → 判 0。AC-8 的 `<p>` 窗口同理（措辞落进表格/标题会串段）。
2. **堆叠糊数**：`grep -oE "调研结论 G[0-9]+" | sort -u | wc -l` 对"9 个编号挤在同一行"照样给 9 —— 唯一集数量看不出违规（探针实测：2 条标签挤 1 行 → `occ=2 / lines=1`）。需求侧交接提示 ① 正是此点。
3. **手抄即腐**：`README.md` 的 7 条差异（D1-D7）全部来自"文档抄代码、代码变了文档没跟"。本轮又实测到一例**唯一基准自身的小漂移**：`BASELINE-code-facts.md:35` 记 `Detail`「含 6 个 tab 组件」，而 `frontend/src/pages/Detail.tsx:9` 的 `TABS` 与其 `*Tab` import 均为 **5**。若交付稿照抄 6，AC-1"与 BASELINE 一致"反而把错数字固化。

同时，AC-12 禁 L1 写入 → 不能靠"写个生成器/校验脚本"解决（那是第二套工具，还要人维护，且落 `frontend/`、`backend/` 即越界）。

## Decision

1. **每个数字与清单只有一个真源**：规模数字与域/页归属 = `BASELINE-code-facts.md` §1/§2；竞品 G 号、去向与需代码议题 slug = `RESEARCH-competitors.md` §2；应用侧入口与页面清单 = `frontend/src/App.tsx`（`NAV`/`ADMIN_NAV` 的 label 原文、`./pages/*` 的 32 个挂载）；视觉值 = `frontend/src/styles/tokens.css`。交付稿**只呈现派生结果，永不成为真源**。
2. **一致性用单行派生命令对账**，集中写进 DESIGN §1.5 的 K 系列（K1…K11）（缺则报缺、多则报多），不另立脚本文件。编号以 DESIGN §1.5 为唯一列表，本处只述意图：
   - **K1** 结构计数与页名集合 `comm` **双向**对账（缺页 / 虚构页两个方向都要空；域章数 == `BASELINE §2` 现算域数；page 块数 == 32）；
   - **K2** `data-anchor` 逐条 `[ -f ]` 存在性（消灭"看着像引用"的空标）；
   - **K3** `data-owner`（归属四值）与 `data-state`（标注三态）**值域闭集**，两轴不得互相代偿；
   - **K4 / K4b** 融入块与议题 slug 集合与 `RESEARCH §2` 现算值 `diff` 为空，并加**堆叠探测** `occ == lines`；
   - **K5** 入口 label 集合与 `App.tsx` 现算值 `diff` 为空（13）；**K6** 六处待标注 `id="nb-*"` 计数 **恰好 6**（数量地板只防"漏光"，不防"一处代表全部"）；
   - **K6b** 内联的每个 CSS 变量在 `tokens.css` 有**同名同值**声明（自造变量名即红，如探针里的 `--radius-legacy`）；
   - **K7 / K8** AC-7 / AC-8 的**节点锚定加严版**（`id="sec-security"` / 每处「加密」在自己的 `<p>` 内且同行含限定语），与已投票命令同跑，两版不一致即判不合格；
   - **K9** 每个融入块的 `id="vb-G<n>"` 集合 == 现算"融入原型"G 号集合（当前 9 条）。
   - **K10** 校准基线严格式（7-40 hex SHA ＋ 日期同行 → ≥1），把"基线新鲜度"从人眼核对变成机验；
   - **K11** 禁词闸 `grep -cE '攻击面|弱点(总表|清单)|S1-S10' "$F"` → **0**：D11"不得集中搬运内部弱点"的机验面（G2 🔴 B-1 补——此前 D11 只有声明无判据，反例附录稿实测命中 `1`、合格稿 `0`）。
3. **基准与代码冲突时以代码为准并上报**：交付稿按实测值写，差异以一行上报需求侧改 `BASELINE`（本轮已上报 `:35` 的 6→5），**禁"两边都写"式含糊**，也禁 Architect 直接改已投票工件。
4. **标记字面串即接口名**：AC 命令里出现的 `class`/属性/`id` 串是契约；2a/4-dev 改视觉自由，改字面串必须**同笔**改 `REQUIREMENT.md` 该条命令并记票面（DESIGN D5）。

## Consequences

**正向**

- 交付稿里的每个数字都可回到真源复算，README 式漂移在本 change 内不可复发；错数字（如 tab 数）会被 K2/`[ -f ]` 与上报通道暴露，而不是被验收固化。
- 词锚定 → 节点锚定，堵住已实测复现的假绿通道；票面命令不动，加严版进 5-test。
- 无新工具：只有可复制的单行命令，评审者能自己跑。

**负向 / 长期债**

- 派生命令对**文档格式**敏感（依赖 `\| N \|` 行形、`\|` 分隔列序、`tokens.css` 的 `--x:y` 形态）。真源重排 → 命令静默失配（表现为"数不出东西"而非报错）→ 缓解：命令集中在 DESIGN §1.5 一处可改；`docs-drift-resync` 的 AC 须含"K 系列全跑通"。
- 交付稿比"照抄更顺眼的清单"啰嗦：一行一条记录、逐块打标、每个变量同名同值。这是刻意的。
- K 系列闸**未进票面**（除已投票的 AC 命令本身）。若 5-test 只跑 AC 原文命令，R2/R3 两条通道会重新打开 —— 已在 DESIGN §1.5 与 §7 出口自检把两版并跑固化。

**推翻本 ADR 的代价**：高。改"派生"为"手抄/生成器"等于同时改 9 条 AC 的判据本体，并要重开需求门票面。
