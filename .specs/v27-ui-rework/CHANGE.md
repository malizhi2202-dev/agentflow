# CHANGE: AgentFlow UI 重构与导航交互统一

- **Change ID**: v27-ui-rework
- **创建日期**: 2026-10-27
- **路径建议**: 完整
- **状态**: active

---

## Why（为什么做）

当前 UI 虽已完成部分页面壳层统一，但整体仍存在三个直接影响使用的问题：

1. 视觉上偏暗、偏平，页面之间主要靠同质面板和表格堆叠，用户难以快速判断当前页面重点。
2. 导航状态与详情状态分散维护。点击左侧导航进入另一个栏目时，旧的项目 / Agent / 工具 / 角色 / 工作流详情态可能继续拦截渲染，导致左侧选中项与实际内容不一致。
3. 页面缺少稳定的信息层级。摘要、主工作区、辅助信息、详情和编辑之间没有统一关系，用户需要自行理解下一步动作。

本次改造的目标不是继续修补单个页面，而是在不改变业务能力的前提下，建立一套可复用的 UI 层级和导航行为。

## What（做什么）

以「极简」为视觉调性，重构 AgentFlow 前端应用壳层、导航状态、页面层级和五类高频页面的内容组织：统一全局导航与详情切换行为，建立页面标题 / 上下文 / 关键动作 / 主工作区 / 辅助区的结构，统一设计 token 和基础组件，并为列表、详情、编辑、加载、空态、错误态建立一致的交互约定。首批明确覆盖以下入口及其现有详情 / 编辑入口；保持现有后端 API、数据模型、权限语义和核心业务流程不变。

| 业务域 | 一级入口 | 首批页面路径与上下文 |
|---|---|---|
| Agent | `agents` | Agent 列表 → Agent 详情 / 创建 |
| 项目 | `projects` | 项目列表 → 项目详情 → Agent 详情 |
| 自动化 | `automations` | 自动化列表 / 配置 / 回放入口 |
| 任务 | `tasks` | 任务列表 / 看板 / 任务详情入口 |
| 编排 | `orchestration` | 编排列表 → 新建 / 编辑 / 文档 |

本批以 SPA 内的导航状态为唯一事实源：点击左侧一级入口必须关闭所有不属于目标入口的旧详情 / 编辑态，并让左侧高亮、页面标题和实际内容同步。本批不重新设计 URL 参数、浏览器 history 或深链协议；现有路径兼容和 URL/history 完整同步列入 v2 议题。对于现有 URL 初始化、刷新、前进后退和深链解析，本批只做回归保护，不改变其当前语义；左侧一级导航切换不得偷偷改写 URL、history 或既有深链参数。
## 视觉调性（前端项目必填，由 0-change 步骤 0.6 预选填入）

- **选定**：2 极简（Minimal）
- **理由**：AgentFlow 是高频使用的 Agent 工程与编排控制台，需要用中性视觉、清晰层级和克制留白降低认知负担，而不是增加装饰。
- **参考产品**：Linear、Vercel、Stripe（产品端）
- **明确排除**：玩具（会削弱工程工具的可信度）、复古未来（装饰会干扰操作）、极繁（会放大当前信息平铺和视觉噪声问题）

## 范围排除（这次不做）

- 不修改后端 API、数据库模型、迁移、权限规则或业务状态机。
- 不在本次引入新的 UI 框架、状态管理库、图标库或远程字体依赖。
- 不一次性重做未列入首批的低频入口；首批未列出的页面只接受壳层兼容，不以视觉重构完成计。
- 不新增产品能力；本次只改善已有能力的呈现、导航和交互可理解性。
- 本批不重新设计 URL 参数、浏览器 history 或深链协议；这些进入 v2 议题。

## 验收线（粗粒度，不是 AC）

- 对五个一级入口分别执行以下 10 条组合路径：`agents → projects`、`projects → agents`、`automations → tasks`、`tasks → orchestration`、`orchestration → agents`，以及反向 5 条；每条都从列表进入该入口的详情 / 编辑态后点击目标左侧入口。结果必须同时满足：旧详情态卸载、目标列表页出现、目标左侧项高亮、目标页面标题出现、旧页面特有控件消失；左侧切换不得改写当前 URL / history / 深链参数。
- 每个入口至少验证一次“列表 → 详情 / 编辑 → 返回列表”和一次“列表 → 详情 / 编辑 → 跨一级入口 → 再回原入口”；返回后的内容必须由当前入口状态决定，不得依赖已卸载页面的隐式 state。
- 五类页面统一采用可观察层级：页面标题最大且只出现一次；标题下紧接上下文 / 状态摘要；页面主动作位于标题区或工具栏右侧且每屏最多一个主动作；主工作区先于辅助信息；辅助信息使用更小字号和弱化边界。适用的 loading / empty / error / success 状态必须分别有可见状态文案或标记，error 必须有重试 / 返回动作，empty 必须有下一步动作；不适用状态在 `REQUIREMENT.md` 的状态矩阵中登记理由。
- 统一视觉基础在五类页面可见且可复用：页面标题、摘要、主动作、内容区和辅助区遵守同一层级规则；自动化测试、构建、键盘焦点 / reduced-motion 基础检查和上述关键路径浏览器走查通过。
- 权限不变量保持不变：前端只是导航和呈现，不是安全边界；既有 API 请求、服务端资源授权、无权编辑和未授权访问行为不得因 UI 重构变宽松。至少覆盖一条未授权 API / 资源访问回归和一条前端入口回归。

## 风险与未知

- 当前页面仍有较多内联样式，迁移基础 token 和组件时可能暴露局部样式依赖。
- 视觉重构可能影响既有页面快照或依赖具体文案 / class 的测试，需要逐项更新而不是批量掩盖。
- v26 尚有人工浏览器走查欠账，本 change 将把关键导航和高频页面走查纳入正式验收。
