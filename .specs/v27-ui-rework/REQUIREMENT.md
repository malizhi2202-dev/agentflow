# REQUIREMENT: AgentFlow UI 重构与导航交互统一

- **Change ID**: v27-ui-rework
- **状态**: active

## 用户故事

### US-01 · 统一导航切换
作为 AgentFlow 使用者，我想从任意详情或编辑态点击左侧一级入口后直接进入目标列表页，以便不会被旧页面状态拦截，也不会误以为切换失败。

### US-02 · 可扫读的页面层级
作为需要高频操作 AgentFlow 的工程用户，我想在每个首批页面先看到页面目标、上下文、状态和主要动作，再进入主工作区，以便快速判断当前页面和下一步操作。

### US-03 · 一致的列表、详情和编辑返回
作为处理 Agent、项目、自动化、任务和编排的用户，我想在列表、详情、编辑之间使用一致的返回和切换行为，以便不需要重新学习每个页面的导航方式。

### US-04 · 诚实的异步状态
作为等待或排查数据的用户，我想看到明确的 loading、empty、error、success 状态和下一步动作，以便知道系统正在做什么、是否需要重试或开始创建。

### US-05 · 保持既有权限边界
作为平台管理员或普通用户，我想让 UI 重构不改变现有权限和服务端授权行为，以便视觉改版不会造成资源越权或操作范围扩大。

## 验收准则（AC）

### AC-01 · 一级入口切换清理详情态

- **Given** 用户已登录，当前在 `agents`、`projects`、`automations`、`tasks` 或 `orchestration` 任一列表页的详情 / 编辑态
- **When** 用户点击另一个左侧一级入口
- **Then** 目标一级入口列表页渲染；旧详情 / 编辑内容不再可见或响应交互；目标左侧项带 active 状态；目标页面标题出现；旧页面特有标题或控件不再出现
- **验证**：前端导航回归测试覆盖 10 条正向 / 反向组合路径，并检查 DOM 中目标标题、active 项和旧详情标识

### AC-02 · 列表、详情、编辑返回

- **Given** 用户从五类入口列表进入任一可用详情或编辑态
- **When** 用户执行查看详情、进入编辑、取消编辑或完成保存
- **Then** 查看详情进入对应详情；进入编辑保留当前资源上下文；取消编辑回到对应详情；保存成功回到该资源详情；保存失败保留表单输入并显示可理解错误与重试 / 再次提交动作；点击页面提供的返回列表动作回到对应一级入口列表
- **验证**：每类入口至少一条组件测试或集成测试，覆盖详情 → 编辑 → 取消和详情 → 编辑 → 保存成功 / 失败各一条适用路径

### AC-03 · 跨入口后回流

- **Given** 用户在任一首批入口的详情 / 编辑态
- **When** 用户切换到另一个首批入口，再点击原入口
- **Then** 原入口显示列表页而非上一次残留的详情 / 编辑态；原入口 active 状态正确；页面不依赖已卸载组件保存的隐式 state
- **验证**：覆盖至少 5 条跨入口后回流测试

### AC-04 · 既有入口兼容

- **Given** 用户通过现有 URL 初始化页面，或当前页面存在既有浏览器 history / 深链上下文
- **When** 用户刷新、后退、前进或直接打开现有入口
- **Then** 本 change 不删除现有入口、不改动既有 URL 参数和深链解析；当前 v1 不新增 URL/history 写入，也不承诺建立新的统一路由模型；左侧一级切换的本地详情态清理由 AC-01 / AC-03 单独验收
- **验证**：运行现有 URL / 路径相关测试；保留刷新、后退、前进和既有入口渲染回归；v1 不新增路由协议测试

### AC-05 · 页面级层级

- **Given** 用户打开五类首批页面中的任一列表、详情或编辑页面
- **When** 页面完成渲染
- **Then** 页面标题只出现一次且是当前页面最大层级文字；标题下方存在上下文或状态摘要；最多一个主动作位于标题区或工具栏右侧；主工作区先于辅助信息；辅助信息使用更小字号和弱化边界
- **验证**：页面结构测试检查语义标题、主动作标识、主工作区容器和辅助区容器；人工走查记录五类页面截图或清单

### AC-06 · Loading 状态

- **Given** 首批页面的数据请求尚未完成
- **When** 页面进入加载态
- **Then** 页面显示明确的加载文案或可访问的 loading 标识；主工作区不显示误导性的空数据结论；请求完成后加载标识消失
- **验证**：对每个实际存在异步请求的首批页面使用 mock 延迟请求测试

### AC-07 · Empty 状态

- **Given** 首批页面的数据请求成功且返回空集合 / 无现有资源
- **When** 页面完成渲染
- **Then** 页面显示明确的空态说明，并提供与当前页面目标匹配的下一步动作（如创建、配置或返回）；不显示伪造统计或假数据
- **验证**：对每类入口至少一个空集合 fixture 进行组件测试

### AC-08 · Error 状态

- **Given** 首批页面的数据请求失败
- **When** 页面完成错误渲染
- **Then** 页面显示可理解的错误提示，并提供重试或返回动作；错误区域不泄露凭据、内部堆栈或未转义的服务端文本
- **验证**：对每类入口至少一个失败 fixture 进行组件测试，并执行敏感文本断言

### AC-09 · Success 状态

- **Given** 首批页面的数据请求成功且返回有效数据
- **When** 页面完成渲染
- **Then** 用户能看到真实数据、当前上下文和主要动作；页面不以 loading 或 empty 状态覆盖有效内容
- **验证**：现有成功路径测试继续通过，并为每类入口保留一条真实结构断言

### AC-10 · 权限不变量

- **Given** 用户无权访问资源或执行编辑操作，或攻击者篡改 URL、路由参数、本地状态、详情缓存或直接构造 API 请求
- **When** 用户通过五类入口任一读 / 写路径、直接访问现有资源上下文或直接触发既有 API 请求
- **Then** 服务端仍对每次资源访问和写操作执行最终授权；UI 不根据客户端可篡改状态、旧详情缓存或过期异步响应授予权限或短暂展示跨资源数据；既有未授权结果与错误语义保持不变；错误展示不暴露资源是否存在、凭据、堆栈或未转义外部文本
- **验证**：运行未授权读 API、未授权写 API、篡改资源参数、篡改本地状态四类回归中的适用项；五类入口至少各保留一条前端入口权限回归；检查错误提示不包含敏感服务端文本

### AC-11 · 键盘与动效

- **Given** 用户使用键盘或系统开启 `prefers-reduced-motion`
- **When** 用户在五类首批页面执行一级导航、返回、打开详情 / 编辑、取消和重试
- **Then** 所有动作可通过键盘到达并触发；当前焦点有可见指示；切换后焦点落在新页面标题或第一个可操作控件；系统要求减少动效时不播放非必要过渡
- **验证**：键盘走查清单覆盖五类入口；自动化检查 focus-visible 标识和 reduced-motion 样式规则

### AC-12 · 操作反馈

- **Given** 用户提交保存、删除、配置或重试等已有写操作
- **When** 操作处于进行中、成功或失败
- **Then** 进行中状态禁用重复提交并提供可感知反馈；成功状态显示一次可读的成功反馈并落到该资源详情；失败状态保留用户输入并将焦点移至错误摘要或重试控件；错误、成功、加载提示使用可被读屏器感知的状态区域（如 `role="status"` / `aria-live`，具体组件规则进入 UI-DESIGN）；不把静默消失当作成功
- **验证**：对五类入口中实际存在的写操作至少覆盖一条进行中、成功和失败 fixture；不适用操作在状态矩阵中登记

## 范围切分

### v1（本次必做）

- 应用壳层与一级导航协调逻辑，以及全部详情 / 编辑态之间的清理协调
- Agent、项目、自动化、任务、编排五类入口的壳层和页面层级统一
- 基础设计 token、标题区、工具栏、主工作区、辅助区、状态反馈约定
- loading / empty / error / success 的适用状态覆盖
- 现有入口兼容回归；不在 v1 引入新的 URL/history/深链协议
- 键盘焦点、reduced-motion 和权限回归
- 关键路径自动化测试与人工浏览器走查

### v2（下次再说）

- URL 参数和详情 / 编辑路由合同重新设计
- 浏览器 history 与深链的完整统一模型
- 五类入口之外的低频页面全面迁移
- 全站视觉快照基线与逐页视觉回归系统

### out（永远不做）

- 本 change 内新增业务能力或改变后端 API、数据库模型、迁移、权限规则、业务状态机
- 以 UI 隐藏代替服务端授权
- 引入新的 UI 框架、状态管理库、图标库或远程字体依赖

## 非功能性需求

- **性能**：不引入新的运行时依赖；页面切换不得因本 change 增加额外网络请求；前端构建必须继续通过，产物体积如有变化需在 TEST 中登记原因。
- **可访问性**：语义标题唯一且层级正确；交互控件可键盘访问；保留可见 focus；支持 `prefers-reduced-motion`；状态提示可被读屏器感知。
- **安全**：服务端仍是唯一授权边界；客户端不得根据可篡改的 URL、路由参数或本地状态授予权限；错误文案不得泄露密钥、堆栈、资源存在性或未转义外部文本；不新增客户端信任输入。
- **兼容性**：保持现有 React / TypeScript / Vite / Zustand 技术栈和已支持浏览器范围；不删除现有入口，不在 v1 引入新的 URL / history / 深链协议。
- **可观测性**：本 change 不新增业务埋点；失败状态必须在 UI 可见且有恢复动作。

## 状态矩阵登记

| 页面域 | Loading | Empty | Error | Success | 备注 |
|---|---|---|---|---|---|
| Agent 列表 | 按请求 | 按请求 | 按请求 | 必做 | 列表请求单独登记 fixture |
| Agent 详情 / 创建 / 编辑 | 按请求 | 按请求 | 按请求 | 必做 | 详情加载和保存请求分别登记 |
| 项目列表 / 详情 | 按请求 | 按请求 | 按请求 | 必做 | 项目请求按实际接口登记 |
| 自动化列表 / 配置 / 回放 | 按请求 | 按请求 | 按请求 | 必做 | 配置和回放仅覆盖实际异步操作 |
| 任务列表 / 看板 / 任务详情入口 | 按请求 | 按请求 | 按请求 | 必做 | 无独立请求的看板列不重复造状态 |
| 编排列表 / 新建 / 编辑 / 文档 | 按请求 | 按请求 | 按请求 | 必做 | 静态文档无请求时登记“不适用” |

> “按请求”表示：该页面存在对应请求就必须覆盖；不存在对应请求时在任务摘要中记录“不适用 + 代码依据”，不得用假请求制造状态。
