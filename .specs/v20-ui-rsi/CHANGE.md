# CHANGE: 记忆中心与提案抽屉（RSI 治理面首次上界面）

- **Change ID**: v20-ui-rsi
- **阶段**: 0-change（2026-10-24）· 完整链（UI → 2a 不跳）
- **规模**: large（~900 行 store/page + 用例）

## Why

波 6（`64e44de6`）与波 7（`13faefbe`）把 RSI 治理做成了后端契约：记忆四层晋升门、晋升评审账、防污染双扫、
检疫/衰减、四类开关、四熔断、提案三权分离（探针→影子重放→人批发布）。**`grep -rl "api/rsi" frontend/src` = 0**——
治理能力在界面上一片空白，管理员只能靠 curl。

## What

新增侧栏一级入口「记忆中心」，**双 tab**：

1. **记忆 tab**：四层列表（layer/status/kind 筛选）· 写入表单（cue/lesson/evidence 三字段 + confounded + 因果前缀）·
   晋升评审台（`promotion_reviews` 按记忆查）· 检疫（按 source_ref 批量）· 衰减队列（只列不删）·
   顶部折叠「自动化治理」区（四类开关 + 四熔断状态/复位）。
2. **提案 tab**：提案列表（状态 + 预算/已用）· 详情动作（探针录入 / 影子重放录入 / 领域会签 / 人批发布）·
   状态机提示（generated→probed→awaiting_approval→published；`collapsed`/`blocked` 终态说明）· 新建提案（surface 白名单 + 限额）。

## 视觉调性（0.6 · 例外条款锁定）

沿用既有深色工程控制台 + `tokens.css`；参照 `prototype/memory.html`（形态参考，不复制）。不引入新 token/组件库。

## 影响面

- 前端：新增 `stores/rsi.ts`、`pages/Memory.tsx`、用例；`App.tsx` 加入口。
- 后端：**不改**（全部端点已存在）。
- 数据：无 schema/迁移。
- 架构：0.4 检测**未命中**（既有架构内新增页面）。

## 范围排除

1. 金标数据集本体 / judge 模型调用 / 影子重放执行器（后端也无，属 RSI 执行器 change）。
2. 可改面（surface）**新建**：本波只读列表用于提案选择；新建留给管理员走 API（避免本波做 admin 表单）。
3. 记忆的「编辑/删除」（设计里记忆是追加 + 检疫/衰减，不提供就地改）。
4. 提案 Apply 的真实执行（发布只改状态，实际应用仍走既有 Apply）。

## 验收线

记忆写入三字段缺一 → `no_entry` 可见；开关关闭后写入被 409 拒；提案发布需管理员且必须 `awaiting_approval`；
`tsc` 0 / `vitest` 全绿 / `build` 绿。

## 风险

| # | 风险 | 处理 |
|---|---|---|
| R1 | 提案动作多，界面容易做成"按钮堆" | 按状态只显示**下一步合法动作**，其它动作给说明 |
| R2 | 发布是不可逆外部动作 | 二次确认 + 仅在 `awaiting_approval` 显示 |
| R3 | 审批角色（管理员）在界面上无感知 | 发布按钮对非管理员置灰并给 title 原因（后端仍拦） |
| R4 | 证据数组表单难用 | 用「每行一条 ref」的文本域解析为数组，附格式说明 |

## 1.5 压测（SCAMPER + 逆向，摘要）

- **消除**：不做记忆编辑（设计不支持）；不做 surface 新建（本波省掉 admin 表单）。
- **逆向**：怎么把这页做糟？——把所有 RSI 字段一股脑平铺。对策：按"记忆 / 提案"两个心智切，治理收进折叠区。
- 6 问结论：最不需要的是单人开发者（无提案）；最先翻车是"误发布"（故二次确认 + 状态门）；砍一半先留记忆列表+写入+开关。
