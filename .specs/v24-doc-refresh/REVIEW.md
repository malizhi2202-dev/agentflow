## 第三轮 · 自造缺陷复盘（照 ui-parity 的教训）

1. **第一版脚本用错 class**：生成芯片时用了 `mono` 而非 `chip warn`，导致 §3.3 除一行外全部未命中——**静默无效**（脚本返回「成功」）。修复：改用正确的 class 生成器 + 加**幂等跳过**（已含 `〔v21 … 回填〕` 标记则跳过）+ 复跑后用**计数**核验（15 → 33 条注记）。**教训：批量改文档必须用「计数核验」，不能只看脚本报没报错。**
2. **shell heredoc 转义吃掉反斜杠**：长脚本走 `bash <<EOF` 被吞 `\"`，Python 报「leading zeros」这种完全不相干的语法错。**教训：超过一屏的脚本一律 `Write` 成文件再跑**，不要走 heredoc。
3. **cwd 漂移**：`cd backend` 后相对路径失效，脚本连报两次 `FileNotFoundError`。**教训：脚本里用仓库根锚定的相对路径，且每次从根目录跑。**
4. **子代理越界风险**（预判）：INDEX.md 那个子代理报告里主动说明「`STATE.md` 的 M 状态不是我改的」——说明它**守住了文件所有权边界**。**教训：文件所有权必须写进 prompt 原文，不能靠默认。**
