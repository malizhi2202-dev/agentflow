外部消息渠道 · IM 进出站 消息传递域 · 对齐 Multica channels

先把层划清，别混：上面三区是平台 ↔ 外部系统（A2A 卡片 / 契约 / 可观测出口）；本区只管一件事——IM 消息怎么进出、谁能触发、回复回到哪。凭据与连接卡片不在这里：Agent 级 IM 六卡在Agent 详情「能力 · 集成」（integrations 行 · 断开=软撤销 · 密钥写-only · 改密钥 = 断开重连——这三条本页不改写，沿用同口径），会话内那条渠道绑定条在对话中心。本区零开关：只有语义呈现，不提供连接 / 解绑 / 换凭据 / 改白名单任何动作——与上面三区的冻结纪律同一条（§6.0 + §6.27）。

账号绑定 · 一次一链路

  1. IM 侧用户首次 DM 该 Bot（此刻平台还不知道他是谁）→ 只收到一条绑定链接：不回答问题、不起 run、不进会话。
  2. 点链接 → 登录 → 把该 IM 账号关联到工作区成员身份（即 §6.4 的 redeem 链接双因子绑定：IM 账号 + 平台账号各认一次，同一条链不另起一套）。
  3. 绑定完成后才真正跑 Agent——绑定前的一条消息不入库为 run，只留一条待绑定事件。
  4. 每条入站消息都重校验：绑定是否还在 + 该成员是否还在空间；离空间即失效（不等下次同步，当条直接拒）。

绑定只回答「发信人是谁」：它不会把平台里其他人自动拉进工作区，也不因为群里有人 @ 了 Bot 就给未绑定成员开权限。绑定 ≠ 准入：能不能触达仍由各通道的 allow_from 白名单决定（空名单 = 全拒，不是全放 · §6.4 同口径）。

开启 A 档 · AF_ENABLE_METRICS=true？

env 开关 = 对外面变化，按纪律二次确认。此页只读呈现生效值，确认结果是生成写入建议（供部署侧应用），本平台不热改自身进程环境。

  • 打开后 GET /metrics 对外可读：RED 指标 + 直读现表 Counter/Histogram（MySQL）
  • 暴露内容：域/能力名、运行计数、耗时直方图、token 汇总（不含会话原文与凭据）
  • 需配 excluded_handlers（健康检查与 /metrics 自身不打点）
  • 不改变 trace_spans 仍 0 行的事实——B 档此刻打开也无东西可导（前置 C10-0）
  • 撤销成本低：清 env 重启即下架（见「撤销已开的对外面」）
