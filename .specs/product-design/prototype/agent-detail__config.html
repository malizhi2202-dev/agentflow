密钥写-only · 保存前在线验证（400 / 409 分支）· 改密 = 断开重连：通道密钥与 6 区 env 同一颗保留哨兵 ****——界面只写不读，永不回显明文。提交前平台拿这条密钥真打一次对端再落库：400 = 对端拒绝（凭据无效 / 机器人权限未开 / 回调地址不匹配），行内显错且不落库；409 = 「通道 × Agent 唯一 bot」冲突——同一通道本 Agent 只能挂一个 bot（同渠道重复连接，或换端点未先断开旧连接），须先断开旧连接再连。两分支都不落库、旧配置原样不变。改密没有「原地更新」：界面读不到旧值，服务端也拒绝原地替换活动凭据——只有 断开 → 重连 两步，中间该通道停止入站（在途 run 不受打断）。

灰置两态（都不可点、但含义不同 · 行尾均注门）：未启用 = 平台级配置门 channel_providers.<id>.configured = false（本工作区没装这个 bot，如企业微信）——整卡预览态、不给连接入口，安装申请只在 admin 全局设置渲染，不是本 Agent 缺权限；预览 = 平台能力门（如 Telegram 传输层尚未实现）——如实标注而非漏配，只渲状态不给入口。两态都不落库、不影响已连通道；configured 转 true 后本行自动放开「连接 ▸」。

断开 = 必填原因 + 软撤销保留审计：断开不是物删——通道行转 unbound，原因与操作者入审计（im:unbound）；凭据留平台加密态（写-only，界面永不回显）、入站会话历史与快照保留、「通道 × Agent 唯一 bot」槽释放 → 重连免 409；重连走同一套遮蔽输入 + 在线验证，历史会话延续不另起。在途 run 不打断，只是不再接收该通道的新入站；本 Agent 侧断开不改平台级安装（撤销凭据、卸载 bot 去 integration.html）。

不进全字段草稿槽：本区每个动作都是一次独立请求（PUT /api/agents/1/channels · 带在线验证）——连接 / 断开 / 改密 / 白名单增删当场校验当场生效，不随页底「保存全部」提交，也不被「放弃」清掉；与 6 区 env（专用端点 + rev 乐观锁）、8 区 MCP（即存）同属例外口径（见 草稿槽与同源映射）。
