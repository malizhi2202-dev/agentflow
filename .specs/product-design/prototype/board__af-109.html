「已指派」不等于「在运行」：本项的 Agent 负责人只表达归属与默认可执行者；指派要走的确认框里点了「开始」才建 run（选「先不开工」或本项停在停车闸内 = 只有归属、没有运行，层形态 board.html#md-assign-confirm）；改派、改状态、取消指派都不中断在跑的运行——要打断得显式点「停止」（本页 run 行 / 看板行内均有该动作）；关闭（cancelled）≠删，同样不触碰 run；只有删除任务才连带取消未完成 run。

平回复路由三步（无 @ 时的默认走向，逐条背下来）：① 回复某条 Agent 评论 → 交该 Agent；② 在 Agent 参与过的讨论里回复 → 保持该 Agent（不必每条重 @）；③ 顶层无 @ 评论 → 交任务的 Agent 负责人（负责人=小队时交 leader）。两条例外：直接回复「人」的评论不回落到负责人（那是人和人说话）；写了显式 @（哪怕只 @ 人）即放弃回落——自动路由整个让位于显式目标。

运行焦点与结果回流（四入口共用的两句）：① 本次运行的焦点 = 这条触发评论 + 同批合流进来的评论，不是整个任务——被 @ 一次不等于接管本项（接管=指派）；计划并入的评论集与实际投喂列表分两个账（同 squads__code-review 「计划 vs 收据」口径），才答得出「它为什么只跑了一次」。② 进度回到你触发它的界面：从这条评论起的 run，回流贴在本评论流 + 本页 run 历史；执行日志记全量（本页 run 历史表逐行「回放」→ replay.html）。一处兜底原则：拒绝 Agent 自己冒出来——没有第三个去处，不会顺手把结论抄去别的地方。
