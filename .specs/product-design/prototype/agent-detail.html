与看板统一抽屉 dr-task 的「改状态 ▾」同一组件、同一门禁（状态×角色）。状态名对应的内置 key 与行为只挂在固定 key 上（完整清单见 阶段模型 · 状态-行为锚）：backlog 唯一停车态（指派 Agent 不建 run）· in_review（审核中）结束该任务上的自动化运行 · blocked 承接失败处理 · in_progress 上 run 失败回收回 todo；done / cancelled 上指派也会立刻开跑（停车不是类别属性）。自定义态（如 Code Review / QA）只继承生命周期类别，这四个行为一个都不继承——把它们并进「Started」一列也不许（分栏按具体状态）。

指派新工作走头部「＋ 指派工作」（会入本 Agent 队列，等并发槽位释放）；任务全量在 看板——本标签页即看板 scope「指派给：本 Agent」的同一列表组件，行内「改状态」保持可操作语义。取消不计入成功率（见概览口径）。

保存语义分级（一行卡）：低敏即存技能开关 · MCP 操作（另含知识源挂/断、IM 连接——行级即时落库，行尾带「即存」chip）｜ 高敏草稿指令 · 环境变量 · CLI 参数（dirty 切栏拦截 md-discard 已有）——低敏行级即存，高敏显式落库，一句话把双层保存语义落在 AgentFlow 口径。

Access · 四把钥匙分离 能看见 ≠ 能改 ≠ 能跑 ≠ 能读凭据 两轴三档 · 10-23 校正
