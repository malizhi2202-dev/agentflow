看纪律原文

档位详情 · T1 子进程 + rlimit / 专用 uid（过渡带）不承诺

为什么写出来又不进阶梯：契约的 tier 枚举里没有 T1（inproc|container|gvisor|microvm|remote）。它的定位是给「不想上容器但要比 T0 好一点」的过渡实现用，界面与文档都禁止把它当安全边界宣称。

形态
子进程 + setrlimit（CPU/内存/文件数）+ 专用 uid
失效面
弱：防手滑不防恶意——同内核、同文件系统可达面，越权读与提权不挡
冷启动
ms（无镜像拉取）
本机探测
不适用（不提供可选）
能挡住的
失控 fork、内存吃满、跑飞的死循环、单用户文件配额
挡不住的
任意读盘、内核漏洞利用、ptrace 同 uid 进程、网络外联（需另配 netns）
出现在哪
只出现在「过渡带」段落与实测注记里，档位下拉不给它选项
为什么不给徽章
一旦给「已隔离」徽章就会被误读成边界，比现状更危险
晋级路径
要么直接 T2（Docker 已在），要么留 T0 + fail-closed 拒跑不可信输入
对比项T0T1T2
uid 隔离无有（专用 uid）有 + ns
文件系统视野全宿主同宿主（权限位）挂载卷白名单
内核共享是是是
恶意代码假设不承受不承受部分承受
对外承诺「无边界」红条不承诺进阶梯

能装出来吗

档位详情 · T5 云沙箱外接（E2B 类）外接选项 · 不内嵌

「最高隔离强度」≠ 没有代价：物理外移把技术失效面换成了网络、凭据与数据出域三件信任账。E2B 自托管全栈违背单进程承诺；Daytona 因停更出局——所以只作外接选项。

隔离强度 / 失效面

冷启动
快照毫秒级恢复
本机探测
外部服务（不适用本机能力探测 · 需手工登记端点与凭据）
数据出域
必然出域：工作区文件、命令、产物全部过第三方 → 域 owner 显式确认 + 审计
凭据
外部 API Key（平台托管不落明文）· run-scoped 短票仍与档位正交
egress

产物回传

自托管全栈 = 引入一整套外部编排依赖，与「单进程可控」承诺正面冲突

移除 egress 白名单项？

移除即收紧：该目标立即不可达，依赖它的在途执行会失败并被标 egress_denied（不是静默重试）。当前选中：pypi.org:443。

  • 受影响：quant-research 域内 2 个依赖安装类工具（下次执行起失败）
  • 不受影响：已完成的 run 与产物
  • 留痕：审计 isolation_egress_changed（含前后快照）

为什么 T4 在本机连「灰置可选」都不给？

探测开放铁律 ①：装不出来的档不显示可选。/dev/kvm 在本机不可读写（Apple 芯片无 KVM，macOS 上的 Docker VM 也不暴露），所以这一档在本页只作说明存在。

  • 不提供「强制选择」按钮——静默降档与虚假可选都是本设计明确禁止的
  • 要拿 T4：换 /dev/kvm 可用的 Linux 云主机 / 裸金属，本页会自动列出
  • 本机等效替代：T3（gVisor · 无需 KVM）
