怎么组织一次智能体干活 · 五句主线①-⑤ 一行一句 · 句尾深链到各自落地页口径卡（不新增流程，只把已有分散说法串成一条链）
① 任务 · 记录工作（项目组织）→② 触发 · 指派 / @提及 / 对话 / 自动化 = 产生一条运行→③ 运行 · 在某个运行时上完成 · 结果写回触发处→④ 沉淀 · Skill 跨 Agent 复用 · 小队多 Agent 协同→⑤ 通知 · 给人的都进收件箱
句一句人话（本页只定顺序与归属，细节在落地页）深链
①任务是记录工作的地方，相关任务用项目组织——项目不是文件夹，是上下文供给器（描述与资源在运行时注入，不复制进每个任务）。项目管理 → 项目 = 上下文供给器 →
②四种触发只干一件事：产生一条运行——人点名派单 / 评论里真形 @mention 委派 / 对话里点名 / 自动化触发。四入口全景矩阵已在任务看板成文（board.html#four-entry：只有这四条路能让 Agent 开跑 · 不设第五个入口），本页只挂链不重述。任务看板 · 四入口矩阵 → 对话中心 → 自动化中心 →
③运行落在某一台机器（运行时）上完成，结果写回触发它的那个地方：派单来的回任务，评论来的回评论线程，对话来的回会话，自动化来的回自动化记录——与看板四入口底注「结果回流到你触发它的那个界面 · 不设第五个入口」同一条口径。运行时 · 机器侧读法 → 执行回放 →
④沉淀有两条：方法进 Skill，协作进小队——Skill = 可复用成功经验的方法件，跨 Agent 复用（挂多可解挂）；小队 = 多 Agent 协同的一级可指派目标（leader + 成员池）。Agent · 技能绑定 → 能力·技能子栏 → 小队中心 → 技能候选 →
⑤沿途所有给人的通知都进收件箱；Agent 没有收件箱——它被 @ / 被指派 / 被自动化唤起时直接产生运行（事件即运行），机器不读通知。收件箱 · 总句 →

三词解耦（读 ②③ 两句的前提交）：Agent 是身份（配置 · 技能 · 闸门 · 归属）· Runtime 是干活的那台机器（一台电脑 × 一个编码工具 = 一个运行时）· Run 是执行档案（一次执行一份记录，排队只是它的一个状态）。Agent 不是长驻进程，只在被触发时执行——界面上的「在线 / 离线」说的是它的 daemon 与运行时心跳，不是 Agent 本人挂着。机器侧数值与边界表见 运行时 · 数据/执行边界，「Run ≠ 队列项」的展开见 管控面 · 调度底座。

如实注：本页下方现状 / 建议两表的行是组织与归属关系（Team / Project / Domain / User × 七资产），尚无 Runtime 与 Run 两行——它们属执行域不在本页取证范围，故三词解耦挂在本卡，不硬塞成表格行；将来两表补上执行域行时，Runtime 一词的取证挂 runtimes.html、Run 一词挂 replay.html 与 control-plane.html，本卡只改链不改句。
