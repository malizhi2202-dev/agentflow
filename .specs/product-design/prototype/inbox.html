#事件（进箱条件）一句人话
1assigned / unassigned任务指派给你，或从你手上移走（改派走了你也该知道——你手里的活被谁接了）。
2comment · owner · status · priority · date你订阅的任务来了新评论，或其负责人 / 状态 / 优先级 / 日期发生变化——订阅任务上的普通动静都算。
3mentioned任务描述或评论里 @ 你。点名给你，与是否订阅无关、退订也照推；全文在任务上，这里只是指针。
4reactions你建的任务或评论收到表情回应——量小、纯礼节的 ack，恒投递（通知偏好里无开关，见「组外豁免」）。
5task_failed（订阅任务上 Agent 运行失败）重试打满或属「不自动重试」类的运行失败，升格为「需决策」（action_required）进箱——与任务看板 / 告警中心同一出口，不另开一条链。
6quick_create（Agent 快速建单）你用 Agent 快速建的任务或评论：完成或失败都告诉你——它替你落笔，落成了什么得让你过目（恒投递，组外豁免）。
7automation_new · automation_paused你订阅的自动化新建了任务，或因连续失败被系统暂停——自动化默默干活可以，默默停掉不行（暂停通知恒投递，组外豁免）。

父子冒泡不对称：子任务的状态变化向上冒泡给父任务的订阅者（父任务进度只看状态这一行）；子任务的评论 / 优先级 / 日期不冒泡——那些只进子任务自己的订阅者箱，父任务侧不围观细节。

自动订阅 5 个来源（订阅只增不减）：① 任务创建者；② 新负责人；③ 任何评论者（说过话就算关注过）；④ 在描述中被新 @ 到的人；⑤ 自动化预配置订阅者。特别注明：改负责人不移除已有订阅——旧负责人转派走的是「负责人」这一格，订阅名单只增不减，想清净请自己去任务页退订。

退订的边界（权限级规则）：退订只挡该任务的普通动静（第 2 类那串事件）；@你 永远单独穿透——退订 AF-116，王工再 @ 你仍进箱。平台不提供「全量静音」：要让某类事件整体安静，去通知偏好关对应开关（那只停收件箱通知，不停任务上的记录）。

批量操作 4 档（顶栏「批量操作 ▾」）：全部标为已读 · 全部归档 · 归档已读 · 归档已完成 / 已取消任务的通知（本次新增档：任务已终结的残留通知一键清；此档不含 blocked——受阻 ≠ 完成 / 取消，③ 的例外对它不适用）。

读 / 未读 / 归档三态（通知行「⋯ 菜单 ▾」＝右键菜单纯静态等价）：标为未读 = 「我看过，但还没完」——条目回到未读并重新计数，开着抽屉 / 详情页也不会自动清掉，清掉只认你的显式动作；标已读 ≠ 处理掉；归档只收起条目、保留读状态——从归档列表还原时回到原样。

组外 · 三项恒投递豁免（没有开关可关）：① 表情回应；② Agent 快速建单的结果（完成或失败）；③ 自动化因连续失败被暂停的通知。共同点：量小、漏掉代价不对称——让 Agent 替你写了东西、或你的自动化悄悄停了，不该被一个偏好开关掩盖。

与任务级开关的分界：这里管「某一类事件全局进不进箱」；单个任务烦了去任务页退订（只挡普通动静，@ 永远穿透）。两层都只动通知，不动记录。
