改进提案 · 审查流水线 v3配置态自优化RSI · 提案制两拍：快筛 → 终身门

界分（一句话）：reconcile = 运行态自愈（副本 / 健康，管控面自动收敛）⟂ 提案制 = 配置态自优化（拓扑 / 权重 / 阈值，本区）。提案只进人审、不自动应用——机器没有发布权，发布权始终在人（Apply 门不变）。

提案维度（INV ⟂ DOM 正交分栏 · 判别式两句）：「换掉主题就不成立 → 领域类」「换行业仍有帮助 → 不变量类」——例：「审计取证顺序：先 git log 后 blame」属不变量类（怎么工作）；「本仓库 specs 文件名禁中文空格」属领域类（绑定本仓库 specs 知识域）。领域类提案需域成员会签后待人批；dimension 是落库标签（improvement_proposals.dimension，比它只在提示层多一步校验——对方 INV⟂DOM 只在提示层、代码无校验器，我们补上）。双维正交切分搜索空间 = 归因清晰 + 并行不互污。

提案 ≤3 / 对象 / 周 相似已合并 2 频控 + 合并由治理层给；超上限的提案排队到下周，不催办。超时 = 降级「待审不催办」，沉默 ≠ 同意。

预算恒等式 每批应花 = k base + 2k 候选 + k 终身（4k 执行）· 执行数 / 会话数按恒等式事前写死断言，超支少支即失败（停作业并告警）。这是事前契约，不是事后账单；对方（Harness²）常数不抄为我方承诺值——k 由作业预算帽定（本演示批 k=3 · 12 执行 · 3 选择会话，全编造）。「探针执行不计量」是它的自曝缺口，我们不抄。校验失败 = 原文回喂 ≤2 次，仍败继承旧配置（fell_back 留账），不静默复用旧证据。

结构校验集（声明式提案 =「路径→文本」树 · 门禁引擎逐条校，不靠措辞）：体量上限 ✓ 空面拒 ✓ 未触发的技能判错 ✓ 被引用脚本必须随提案附带 ✓ 枚举白名单 ✓ （chip 行示例 = P-1 过审态 · 任一败 = 走左注回喂路：原文回喂 ≤2 次 → 仍败继承旧配置 · fell_back 留账）

自动补触发：技能类提案缺触发行，由平台机械补写而非打回；超体量上限则不补。

提案塌缩熔断 · 已触发 算法：两两行级 Jaccard 均值 ≥0.9 判塌缩（阈值为演示编造，真值待校准）——本批 k=3 候选行级相似 1.0 → 提案塌缩，已停该对象作业并告警（09-20 · 演示行，与 Agent 管控 · RSI 开关卡组「提案塌缩熔断」行同一事件。提案器退化 = 熔断事件，不当计数事件洗白）
