处置面（移除连带发生的事）

对象连带动作口径
其名下 runtime停用他注册的运行时（机器 × CLI）转停用、不再参与派单；不是删记录——机器上的 daemon 若仍在跑，注册与心跳照旧，只是不再有归属人的路由权
其绑定的 Agent归档他 owner 的 Agent 一律软归档（archived_at + 操作者）——可恢复，不静默删除；编排引用与历史 run 全部留在原处
其未完成的 run取消在途与排队的 run 全部取消；已发生的外部副作用不回滚，取消不计入成功率（口径同 agent-detail.html 取消 run）
其在各 Agent Access 上的授权回收 · 且不自动恢复他被加进去的「可运行 / 可见」名单逐项移除。重入职不自动恢复：Access 由各 Agent 的 owner 逐个再授一次——不给「人回来了就全自动有权」留任何口子
其活跃会话与 PAT全部作废与「改角色必旋转会话」同一条纪律：权限变了旧会话不能继续持有变更前权限
可见项目 / 权限点勾选随账号消失project_ids 与 custom_permissions 不转人、不继承

入职与 owner 侧的三条硬规矩

邀请能授什么角色只能授 admin / member 两档。owner 不在邀请路径里——须本人入职后，由既有 owner 提升（换的是「谁拥有这个工作区」，不能让一封邮件顺手改）
邀请链接7 天有效；只出现在邮件正文里，产品内没有任何查看 / 复制 / 再发入口（界面上不留可转卖的凭据）；过期即作废，重发=换新链
最后一个 owner不能降级、不能被移除、不能置离职。必须先由他把 owner 提给继任者，再谈自己的去处——守卫在服务端，不靠界面禁用按钮（与本页 admin「不可改角色 / 不可删除」同源）

本页由 users.html 的 dr-user-admin 抽屉升格而来（权限点表 + 活跃会话撤销操作链，侧栏装不下）。admin 的 6 项权限为恒真豁免、不可削减；改角色与删除在父页即被拒（拒绝原因走 toast）。

本轮（10-23）新增「移除成员 · blast radius 事实清单」抽屉：九条口径为事实校正（离职处置的连带面）。当前后端无任何 offboarding 实现——现在删除账号只删 users.json 一行 + 清会话，runtime / Agent / run / Access 四类全都不动，正是本抽屉要消掉的缺口。演示编造值：2 个 runtime / 3 个归档 Agent / 5 个取消 run / 7 处 Access 回收等计数。与本页既有口径的界分：「历史审计与产物署名留档」沿用父页 users.html 删除弹层的既有结论（追加写不可改删）；「权限变更必旋转会话」沿用 P0-1；「软归档可恢复 · 取消 run 不计入成功率」沿用 agent-detail.html 同名口径。owner 侧三条（邀请只授 admin/member、owner 须由既有 owner 提升、链接 7 天且只在邮件里、最后一个 owner 不可降级 / 移除 / 离职）为政策口径，实现尚未存在。
