演示数据一页两 Tab 装两个正交概念，页头先做 disambiguation（一词一义，禁止混用）：组织层 = 团队 Team（谁拥有资源：成员 + 角色 + 配额 + 审计边界）｜ 执行层 = 协作小队 Squad（这次协作由哪个 leader + 成员池干，是可被指派的一级目标）。两者正交：squad 不拥有任何资产，成本与执行一律归 leader Agent 记账。

两词两义（本页唯一口径）： Team 团队 回答「谁的」——成员册 + 四档角色 + 配额（含对象计数）+ 审计边界；资产表靠 team_id + owner_kind 挂上来。 Squad 协作小队 回答「这次谁一起干」——leader + 成员池 + 协作指令，是看板「指派给…」里的一级可指派目标；不持有资产、不持有配额、不出现在成本归属里（成本与执行归 leader Agent）。反过来用即口径破坏：Team 不可被指派，Squad 不可拥有资源。 Team 与 Squad 无外键关系：同一批 Agent 既被某 Team 拥有，也可被任意多个 Squad 选为成员——「拥有」与「一起干活」是两件事（对齐 实体关系全景 S16 结论）。

指派给小队 = 平台给 leader 入队一条 leader 任务，无成员抢单。成员不会因为「在池里」而看到或抢走这条任务；委派只发生在 leader 的评论流里（写真形 @mention 才算委派）。详见 代码审查小队 · 协作协议。

「拥有」的落点（数据口径）：资产表新增 team_id + owner_kind(personal|team|platform) 两列，首批覆盖 Agent / 工作流 / 工具 / 知识源 / 域五类；存量行默认 personal 且现 owner_id 不动 → 零回填、可回滚、无停机。个人资产可改挂到团队（一次转让 + 审计），挂过来之后原个人不再自动共享。

不做的事（防止概念膨胀）：无部门树 / 无汇报线 / 无嵌套团队（一个资产只属于一个 team，类比 K8s namespace 不可嵌套）；跨团队共享走 owner_kind=platform 与模板市场 published 位，不做「多归属」。Team 与 Domain 正交：Team 回答谁的，Domain 回答在哪跑怎么路由。

审计边界：本队资产的一切操作（成员变更 / 配额改值 / 归属转让）都落 审计日志，可按 team=agentflow 过滤 → audit.html#team-agentflow 深链〔锚点为规划态：审计页尚未接 team= 维度筛选〕。

指派语义（与看板同一口径）：「指派给小队」= 负责人位显示 小队 · 代码审查小队（leader 汇总 Agent），平台给 leader 入队一条 leader 任务（is_leader_task · 同 (任务, Agent) 活跃任务合并去重）。无成员抢单——成员看不到别人的队列，也没有「认领」按钮。

受理门不因小队而绕过：leader 也只拿到接收位，triage 未 accept 前禁止派生执行（自动派单 / 触发规则 / 小队委派同拦）；@mention 指名除外。见 任务看板 的受理门注记。

新建协作小队 Squad

执行层编队：不建资产、不建配额。建完即可在看板「指派给… ▸ 小队 ▸」出现。

同工作区内唯一 · 显示在工作板负责人位 chip 上
leader 必须为 Agent 且不可归档：人不能当 leader（无队列可承接、在线态不由平台判定、成本无主体）。候选口径 = 未归档 ∧ 当前调用者可 canInvokeAgent，选不中的行灰显带拒因（已归档 / 不可调用），不接受自由文本。改设 leader 只影响此后新入队的 leader 任务，在途不迁移。
审查 Agent · 标准审查 Agent · 备援前端 Agent汇总 Agent数据同步 Agent审查 Agent · 旧版（不可选） 李工王工zhangsanwangwu
每人一行可带自由文本角色标签（如「审查人」「前端」）——标签不授予任何权限，只进名册渲染。成员入队仍按链顶人类过「可调用权限」逐次判定，不按小队授权。选进池子只等于「leader 可以考虑派给它」；离线成员照旧 runtime_offline 暂存不丢。
归属只影响「谁能管这支小队」，不影响谁能被它调用；也不改变成本归属（仍记 leader）。
纯文本指令，不是画布节点；平台基础提示（协议 + 名册）由系统拼接，此处不覆盖。
