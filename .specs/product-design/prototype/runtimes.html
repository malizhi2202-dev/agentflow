运行时 · 运行时发现（一台机器 × 一个 CLI × 一个协议族 = 一个运行时）

daemon ≠ 运行时。① daemon 是「一台计算机上」的一个后台进程：随机器常驻、每 15s 向平台心跳一次，负责扫描本机 PATH 上的外部 AI 编码 CLI。② 运行时 = 该机器上「一个被探测到的 CLI 实例」——一台机器 × 一个 CLI × 一个协议族 = 一个运行时；重启 daemon 是更新既有运行时记录，不是重复新建。③ Agent 的每一次 run 一律由对应机器上的 daemon 调用外部框架 CLI（dsh / hermes / codex / claude…）执行，AgentFlow 不本地运行 / 加载模型。

执行位置与数据边界：CLI 本体与其登录凭据（账号 / OAuth / API key）始终留在成员本机，登录归 CLI 自己，平台不接收；平台服务器保存的是 issue、Agent 配置与 run 上下文 —— 其中 Agent 自定义环境变量与 MCP 配置存放在服务端、由 daemon 执行时注入，页面显示受敏感值规则限制（掩码 ***）。

本机适配器探测 · 现状已实现（backend/runtime/adapters/ · get_adapters()）— 目前仅供「运行时监控」消费（RuntimeEvent 观测）；本模块的目标是把探测结果接进运行时注册表与模型目录。探测方式 = CLI 日志目录指纹（非 PATH 探测），解析其 JSONL 会话得 模型 / tokens / 工具调用 / @引用，缓存 60s。数值为演示。

离线语义（daemon 失联时）：① 心跳 15s，异常退出最迟约 3 分钟转离线；② 排队的 run 不立即失败 —— 「重连宽限期 + 入队时长」双条件都满足才置失败；③ 在途 run 随失联失败，可按策略自动重试（原机重连或改派其他在线运行时）；④ 离线 >7 天且无 Agent 绑定的运行时自动清理；⑤ daemon 重启会重新注册本机全部运行时（更新既有记录）并回收未正常结束的 run。

添加自定义运行时（profile）

档案 = 协议族 + 名称 + 命令 + 固定参数；保存后由各机器 daemon 探测解析。仅 owner / workspace 管理员可创建。

空格分词，不接受管道 / 重定向 / &&；profile 全工作区共享，命令由每台机器自行在 PATH 解析。
编辑档案只影响其后领取的 run，在途 run 不受影响。

参数顺序：<你的命令> <你的固定参数> <平台协议参数> <Agent 自定义参数>。平台协议关键参数（-p / --output-format / --permission-mode 等）会被丢弃 —— 请勿写进固定参数。

删除运行时实例「Codex CLI · codex @ 本机」？（演示目标）

删除的是这台机器上这个 CLI 的实例记录 —— 不删自定义运行时 profile（档案仍在，可继续选用）；daemon 若仍在跑，下一轮心跳会重新注册。先处置在绑 Agent：绑定中的行「删除」已置灰不可点。
