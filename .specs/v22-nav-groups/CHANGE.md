# CHANGE: 侧栏导航按业务大类分组（父级标题）

- **Change ID**: `v22-nav-groups`
- **创建日期**: 2026-10-24
- **路径建议**: 最短（压缩路径 `0→3→4→6`）
- **状态**: active

---

## Why（为什么做）

侧栏当前是 **18 个平铺条目 + 1 个「管理」区**：工具库 → 工作流 → … → 审批，没有父级标题。
后果有两个实测过的：

1. **找不到东西**：用户问「用户管理在哪个模块下」——它其实在侧栏最底部，且 1280×720 窗口下被
   `aside{overflow:hidden}` + 不可滚动的 `nav` 裁掉（本轮已修滚动）。功能越多，平铺越难扫。
2. **没有阅读顺序**：从「造资产」到「跑起来」到「谁一起干」到「沉淀」到「看」到「管」是一条业务链，
   平铺把它压成了一条无结构的清单。

## What（做什么）

把 18 个条目 + 告警 + 管理区重组为 **6 个父级标题（组）**，组内保持原有条目与 `id` 不变：

| 组（父级标题） | 成员 | 为什么在这组 |
|---|---|---|
| **构建** | 工具库 · 工作流 · 角色 · Agent | 都是一次性造出来、之后被复用/绑定的资产 |
| **运行** | 编排 · Agent 管控 · 运行时 · 回放 · 自动化 | 「怎么跑起来、跑在哪、跑过什么」——触发与执行 |
| **协作** | 项目 · 任务 · 收件箱 · 团队与小队 · 对话中心 | 人 × 项目 × 组织，任务与消息在这里流转 |
| **知识** | 知识库 · 记忆中心 | 沉淀物（L0–L3 记忆 / 知识资产域） |
| **观测** | 监控 · 告警中心（带未确认角标） | 只读地看现状与异常 |
| **治理** | 审批 · 用户管理\* · 审计日志\* | 不可逆动作与人/权；\* 仍按 `user:manage` / `audit:view` 过滤 |

阅读顺序即业务链：**造 → 跑 → 一起干 → 沉淀 → 看 → 管**。

**② 同批（用户追加要求）：「文档资料 · 原型」入口仅平台管理员可见。**
原型是内部设计口径（含未实现面与规划标记），对普通成员/业务使用者是误导源，因此不再无条件渲染：
`isAdmin` 为真才渲染该链接；成员侧完全不出现（不是 CSS 隐藏）。不新增权限点——沿用 `role === 'admin'`。

## 视觉调性（前端项目必填，由 0-change 步骤 0.6 预选填入）

- **选定**：沿用既有（本项目 v20 已定调，本次不重选、不改 tokens）
- **理由**：本次只增加层级（父级标题），不引入新颜色/字号体系；组标题复用 `--text-muted` + 既有字号阶
- **参考产品**：Linear / Vercel Dashboard / GitHub 侧栏的分组惯用法
- **明确排除**：图标化折叠树、可拖拽排序、二级 flyout 菜单——本次只做「标题 + 平铺子项」

## 范围排除（这次不做）

- 不做二级折叠/展开状态持久化（组常显，靠 `nav` 滚动已可容纳）
- 不动 `PRODUCT-DESIGN.html` 的模块矩阵与原型（`主档` 按「入口名」描述，没有与分组冲突的表述；
  若后续要主档呈现分组，另起 change 走「改 RULINGS → 改主档」）
- 不动 `frontend/src/pages/*` 任何页面
- 不改权限模型（`user:manage` / `audit:view` 过滤规则原样保留）

## 验收线（粗粒度，不是 AC）

- 侧栏出现 6 个父级标题，每个条目仍在且点击后页面与原来一致
- 普通成员只看到「治理」下的「审批」；管理员看到「用户管理 / 审计日志」
- 「文档资料 · 原型」入口只有管理员可见，成员侧不渲染
- 折叠态（48px）只留图标，不出现组标题
- 1280×720 下滚动可达全部条目（含「用户管理」）

## 风险与未知

- 分组是**信息架构判断**，属偏好类，用户若不认同分组口径需要重排（成本：改 `NAV_GROUPS` 一处数组）
- E2E 脚本按 `aria-label` 点名点击导航（名字未变），风险低；但分组容器若引入 `role` 冲突会影响
  `getByRole('button')` 查询——用例会验证
