# REQUIREMENT: 团队与小队页

- **Change ID**: v20-ui-teams
- **上游**: `CHANGE.md`（G1 4/4 通过）
- **阶段**: 1-requirement（2026-10-24）
- **上下文源**: `CLAUDE.md`（用户选定 `ai_context_doc`）

## 用户故事

1. **作为团队 owner**，我想在一个页面上建团、加人、改状态、把资产归拢到团队，这样我不必用 curl 管理"谁的资产"。
2. **作为团队成员（admin/member/viewer）**，我想看到团队现状（成员/配额/资产），这样我知道自己加入的是什么、还剩多少额度。
3. **作为 squad leader 的搭档**，我想看到小队名单并加人/换人，这样"这次谁一起干"可以自助维护。
4. **作为平台管理员**，我想看到全部团队与小队，这样我能处理跨团队问题。
5. **作为非成员**，我不该在列表里看到别人的团队（也不该被提示"存在但无权"）。

## 验收准则（AC）

### AC-1 · 入口与形态
侧栏出现一级入口「团队与小队」；页面为左列表 + 右侧详情抽屉；未登录不进入（走既有登录壳）。
**验证**：vitest 渲染断言 + 手工点检（`App.tsx` NAV/View）。

### AC-2 · 团队列表与"我的角色"
列表卡片显示：团队名、`slug`、状态（active/paused/archived）、成员数、资产数；空态文案「还没有团队」+ 建团引导。
**我的角色**：后端的 `GET /api/teams`（`_team_dict`）**不返回我的角色**，只有详情 `members` 里有 → 角色在**抽屉摘要**显示（`members` 中 `user_id == 当前用户` 的那条），列表不显示，避免为一行字段改后端契约（本 change 不改后端）。
**验证**：用例注入 2 个团队断言字段渲染 + 空态文案；详情用例断言摘要显示「我的角色：owner」。

### AC-3 · 建团
表单：`slug`（正则 `^[a-z][a-z0-9-]{1,31}$`）+ 名称 + 描述 + 配额（可空）。前端提交前做同一正则校验并给行内提示；后端 400/409 的 `detail` 原样显示；成功后列表刷新。
**验证**：用例覆盖"非法 slug 不发请求"、"409 文案透传"、"成功后重拉列表"。

### AC-4 · 团队状态
可在 active/paused/archived 间切换（archived 为不可逆提示，不自动恢复）；`archived` 后「加成员 / 挂资产」按钮禁用并给出原因。
**验证**：用例断言 archived 时按钮 disabled + 标题文案。

### AC-5 · 成员管理
成员列表显示 `user_id` 与四档角色；可添加（user_id + role 选择）与移除；owner 不可移除、owner 只能通过转让产生——后端口径错误原样显示。
**验证**：用例覆盖添加请求体、移除请求 URL、后端 409 文案透传。

### AC-6 · owner 转让
转让需填新 owner 且**显式勾选 confirm**才可提交；成功刷新详情（原 owner 降 admin 由后端保证）。
**验证**：用例断言未勾选时按钮 disabled、勾选后请求体含 `confirm: true`。

### AC-7 · 资产与配额
显示五类资产计数（agents/workflows/tools/knowledge_sources/domains）与配额（max_members/max_agents/max_workflows）；可按 `kind + asset_id` 挂载 / 释放；冲突（资产已属他队 / 非自己资产 / 配额超限）文案透传。
**验证**：用例覆盖挂载/释放请求体与错误文案；`shortcut` 注释写明"候选选择器待后端 unclaimed 列表"。

### AC-8 · 小队
小队 tab：列表（slug/name/leader/成员数/状态）；建队（slug + name + leader_agent_id + 指令）；成员混编增删（`member_kind ∈ agent|member`）；归档（`leader_bound` 409 文案透传）；归档后在跑 run 不连带取消（界面只改状态，不显示"已取消运行"）。
**验证**：用例覆盖建队/加成员/归档请求与 409 文案。

### AC-9 · 可见性
非成员团队不出现在列表（后端 404 口径）；页面**不显示**"存在但无权"的提示；平台管理员可见全部（由后端返回决定，前端不做授权判断）。
**验证**：用例注入后端只返回 1 个团队，断言列表 1 条且无"无权限"字样。

### AC-10 · 错误与空态
读失败 → 页面横幅（`role="alert"`）；写失败 → 就地错误（保留后端 `detail`）；两类空态都有引导文案（团队空 / 小队空 / 成员空 / 资产空）。

### AC-11 · 质量门
`tsc --noEmit` 0 错 · `vitest` 全绿（既有 63 + 新增）· `npm run build` 绿 · **零新增依赖**。

## 非功能性需求

| 维度 | 要求 |
|---|---|
| 无障碍 | 所有交互控件可键盘操作；表单有 label；状态变化用 `role="alert"/"status"`；禁用按钮给出 `title` 原因 |
| 性能 | 页面首屏一次拉列表；详情抽屉按需拉 `GET /api/teams/{ref}`（不预拉全部团队详情）；写后失效缓存再拉 |
| 安全 | 不在前端缓存凭据/密钥；不新增加密或鉴权逻辑；越权与不存在统一由后端 404/403 决定并把文案透传 |
| 兼容 | 沿用现有 `requestDedup` 读写分工（GET 缓存 / 写不缓存） |

## 依赖与假设

- 依赖：`/api/teams`、`/api/squads`（波 4 已交付）；`requestDedup`（波 8-ui-collab 已修 method 键）。
- 假设 1：`GET /api/teams` 对非成员已过滤（后端 `list_for_user`），前端不再二次过滤。
- 假设 2：小队路由当前**无权限校验**（如实记录，不在本波改后端）。
- 假设 3：资产挂载的 `asset_id` 由用户手填（无候选列表 API）。
