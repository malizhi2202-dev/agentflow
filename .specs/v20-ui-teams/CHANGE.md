# CHANGE: 团队与小队页（Team ⟂ Squad 的界面首次挂载）

- **Change ID**: v20-ui-teams
- **阶段**: 0-change（2026-10-24）
- **规模**: medium（预计 ~700 行 TSX/store + 用例；7 个 task）
- **挡位**: 完整（用户 2026-10-24 选定）· 预估 ~180k–260k tokens
- **change-id 来源**: 自动生成（`v20-ui-teams`，沿用本仓 `v20-*` 命名族，冲突检查：`.specs/v20-ui-teams/` 不存在）

## Why（为什么做）

波 4（`ac839aa0`）把 **Team**（组织层资源容器，不可指派）与 **Squad**（执行层可指派编组，不拥有资产）两个实体做进了后端：`/api/teams`（成员四档 / 配额 / 资产挂载 / 转让 / 状态）与 `/api/squads`（混编 / 归档）都已经在跑。
但**前端一个页面都没有**（`grep -rl "api/teams\|api/squads" frontend/src` = 0）——R5-3/R5-4 的产品价值（"谁的资产""这次谁一起干"）在界面上不存在，用户只能靠 curl。

## What（做什么）

新增一个「团队与小队」一级入口，形态 = **左列表 + 右侧详情抽屉**（与任务页/告警页同一交互骨架）：

1. **团队**：列表、建团、改状态（active/paused/archived）、成员增删（四档角色）、owner 转让（`confirm` 双确认）。
2. **团队资产与配额**：五类资产（agents/workflows/tools/knowledge_sources/domains）挂载 / 释放，配额（max_members/max_agents/max_workflows）现状与超限提示。
3. **小队**：列表、建队（slug/name/leader Agent/自由指令）、成员混编（agent|member）增删、归档。
4. **可见性**：非成员**在界面上不可见**（后端 404 口径），平台管理员可见全部。

## 视觉调性（前端项目必填 · 0.6 步）

按 0.6 的**例外条款**锁定，不再出调性卡片，理由：本项目已有成体系的 design system（`src/styles/tokens.css`：深色工程控制台、`--bg-panel/--border/--blue/--orange/--red`）与 127 页原型基线，用户此前明确「以 product-design 为参考」。

- **调性**：深色工程控制台（engineering console）· 信息密度中高 · 克制动效
- **参照**：`prototype/teams.html` · `prototype/teams__agentflow.html`（形态参考，不复制页面）
- **不引入**：新配色 / 新字体 / 新组件库（沿用既有内联样式 + CSS 变量）

## 1.5 想法压测（0-change 步骤 1.5）

**技法**：SCAMPER（消除/调整）+ 逆向（怎么把这件事做糟）+ 类比迁移（任务页/告警页骨架）。

| 压测 6 问 | 回答 |
|---|---|
| 谁最不需要这个？ | 单人开发者：团队/小队对他们一直是空表，页面像"永远空白的管理页" |
| 上线即翻车最先怪什么？ | 资产手填 id 挂错团队（越权把别人的 Agent 挂进来）→ 后端若只校验 team 归属不校验资产 owner 就出事；本波**只做界面**，风险留档 |
| 预算砍一半保留什么？ | 只保留「团队列表 + 建团 + 成员」；资产与小队延后 |
| 头部产品为何不做？ | 它们把"团队"做成账号体系的一部分（邀请即入团），不单独给"资产挂载"这种管理员动作 |
| 一年后这还是问题吗？ | 是——只要资产仍以个人 owner 为主，就永远需要"归拢到团队"的入口 |
| 最小可验证版本？ | 团队列表 + 详情抽屉（成员只读）+ 建团；能证明"团队在界面上活着" |

**被压测否掉的方向**（记入范围排除，防复活）：
- "团队内嵌任务看板"：任务已有独立页，团队只做归属，不做第二个看板。
- "小队＝可拖拽的协作画布"：v14 已裁定画布不新增动态模式。
