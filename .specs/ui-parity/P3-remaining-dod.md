> 判定：每族「节/信息项可见 + 交互真打端点 + 失败文案透传」才算对齐；规划态必须显式标未接入。

## 6.20 任务看板（`board.html` + 5 个变体）
- 原型自注「此界面尚不存在」，但口径明确：状态四类生命周期（未开始/进行中/完成/关闭）×「待受理」正交；**状态标签不授予行为**（进「进行中」≠ 自动启动 Agent）；受理门只拦自动推导，不拦人点名派发；done 建议「需证据 + 同伴复核」；指派三轨 member/agent/squad（squad = 给 leader 入队 leader 任务，成员不抢单）。
- 现状：`Tasks.tsx` 已含四列、triage、三轨、evidence。**待补**：done 证据门 UI、变体态（`board__mark-done` / `board__af-116` / `board__af-109` / `board__task-new` / `board__assign…`）的交互分支。

## 6.8 对话中心（`chat.html`）
- 语义：1:1 **完全私密**（管理员也看不到）· 不自动建任务（被明确要求时用**你的**权限查/动资源）· 起点无 issue 上下文 · **一条消息 = 一个 run** · 「＋」挂 Project context · 运行时离线 → 消息 **queued 等待上线**（与小队「离线暂存不丢」同口径）· 多轮尽量续接原会话（续不上则新会话，历史都留）· Agent 归档/失去可运行权限后不能发新消息 · 会话归档 = 只读。
- 现状：`ConversationCenter` + `ChatWindow` 已有基础。**待补**：queued 态展示与「等待上线」文案、归档只读态、私密性说明位、Project context 挂载入口、运行中/queued/已归档的列表分组。

## 6.9 知识库（`knowledge.html`）—— 已有 4 节口径
- §0 权限矩阵（谁能读/写一屏定死；越权与不存在同码 404）· §1 公共知识（全局只读、管理员维护、四分类）· §2 知识空间（与项目 1:1、成员读写、非成员不可见）· §3 外部源（只读源级授权、凭据只写不读、未关联空间对普通成员不可见）。
- 现状：`KnowledgeBase.tsx` 有列表与源管理。**待补**：§0 权限矩阵一屏、§2 空间成员（用户与 Agent）读写、§3 源级授权与凭据只写不读的显式表达。

## 6.3 Agent 管控面（`control-plane.html` + 6 变体）
- 三层树：域 → 能力组 → Agent（同一 Agent 可多层归属，不是重复渲染）；根级「未分类」虚拟组（domain_id=NULL）。
- 另挂三块：① RSI 开关卡组（四类产物白名单 + 总闸 + 可改面 SurfaceSpec 四列：可写路径模式/体量上限/结构规则/显式排除）② 调度底座卡组（双通道坦白句、排队 run 过期双条件、reclaim/离线清理、重试政策、并发上限人话版）③ 维护作业区（调和只做状态回收/过期/清理；全库级批量写一律人批）。
- 现状：域树 + 能力组 + 调和台已有。**待补**：RSI 卡组与调度底座卡组的**如实呈现**（数据从 `/api/rsi/switches|surfaces`、`/api/control-plane/cluster` 来）、维护作业区。
