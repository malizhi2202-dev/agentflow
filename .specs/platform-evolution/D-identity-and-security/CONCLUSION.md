# ③ 结论与建议

## 结论

**这是一条「条件性漏洞 + 一处确定性缺陷」的组合，不是体验问题。**

- **条件性漏洞**：身份来自客户端自述（`X-User-Id`）+ 唯一缓解是 localhost 闸门 + 无可信代理处理。
  单机默认部署下闸门有效；**一旦前置同机反向代理，闸门对所有外部请求放行，叠加身份自述即可提权为 admin**。
- **确定性缺陷**：`get_current_user` 在身份缺失时**回退 admin**（`backend/auth.py:181-186`）——
  这是 fail-open 后门，与部署形态无关。
- **确定性缺陷**：口令为**无盐 SHA-256**，且存在硬编码默认口令与「重置为 123456」分支。

**最危险的不是任何单点，而是这三条的组合**：默认口令 + 快速哈希 + fail-open 身份回退。

## 建议（按优先级）

### C1 · 消除 fail-open 身份回退 `P0` 难度：低
`get_current_user` 在无法确定身份时**必须返回 401，而不是 admin**。
这是最小改动、最大收益的一条——它把「未知身份」从「管理员」改回「拒绝」。

### C2 · 身份改为服务端签发 `P0` 难度：中
- 登录签发令牌：**浏览器走 HttpOnly Cookie + CSRF 令牌；程序化调用走 Bearer**（两者并存，一次设计到位）。
- 中间件从令牌解析身份；`X-User-Id` 降级为**调试开关且默认关闭**。
- **照搬 Multica 的关键纪律**：任何客户端提交的身份头（`X-User-Id` 等）在中间件入口**先删除**，
  仅由可信分支重写。这条能一次性消除身份伪造面。
- 前端 109 处引用需同步改造——这是本项的主要成本。

### C3 · 口令改自适应哈希 + 清除默认口令 `P0` 难度：低
- `hashlib.sha256` → **argon2id 或 bcrypt**（带盐、可调成本）。
- **删除** `backend/auth.py:108` 的硬编码 `123456`，以及 `:126-130`「缺失 password_hash 即重置为 123456」分支
  （该分支本身就是一个后门：删除口令哈希字段即可获得已知口令）。
- 首次登录强制改密；提供一次性初始化口令而非固定默认值。

### C4 · 可信代理处理 `P0` 难度：低
引入显式部署模式（如 `DEPLOY_MODE=localhost|behind-proxy`）：
- `localhost`：启用来源 IP 闸门；
- `behind-proxy`：**不依赖来源 IP**，改为要求令牌 + 显式配置可信代理来源；
- **并在启动日志与界面上明确打印当前模式**，避免「以为有闸门」。

### C5 · 域归属双点校验 + 统一 404 `P1` 难度：低
- 域归属校验在**入口与中间件各做一次**（照搬 MUL-2600 的 catch-all 思路），并在注释中写明
  「不假设前一处覆盖了所有入口」。
- 越权与「资源不存在」**统一返回 404 而非 403**，避免用状态码探测他人资源存在性。

### C6 · SSE 通道独立重新鉴权 `P1` 难度：中
`/api/runtime/stream` 是第二条数据通道，**必须独立重新授权，不得继承 HTTP 层的信任**。
Multica 的原话即为此：`scope_authorizer.go:96-101`「The realtime layer must not weaken this」。
否则「HTTP 挡住了但 SSE 漏了」会成为隐蔽越权面。

### C7 · 审计 fail-closed `P1` 难度：低
审计写入失败时**不得降级放行**（照搬 `agent_env.go:156-168`：写失败则拒绝返回明文/回滚更新）。
现状 `audit.jsonl` 有 1 万行轮转只留 5 份的限制，也应在文档中写明**历史不可查**的后果。

### C8 · 「状态收敛是主防线」`P1` 难度：中
用户停用/移除时，**同一事务内**归档其 Agent、取消其任务、强制离线；
**不能只吊销令牌**（Multica `workspace_revoke.go:32-37` 的实证）。

### C9 · 看 / 跑双谓词拆分 `P1` 难度：中
把「能看见」与「能触发」拆成两个谓词：admin 的特权**只存在于「看见」侧**。
理由引用 Multica 的具体越权路径（admin 触发他人 private agent → 经其连接读他人邮箱）。
这条与 S1 的 C1（`assignee_type=agent`）直接耦合：**「能被指派」不等于「能执行」**。

## 明确不做（本轮）

- **不做外部 IdP（OIDC）作为默认**：与「clone 即跑」冲突，保留为可选增强。
- **不采用纯共享密钥方案**（方案 A）：密钥仍是客户端持有，且无法撤销单个会话。
- **不把「置于鉴权反代后」当作唯一答案**（方案 C）：那是把安全责任外推，
  且当前连风险本身都未写明。
