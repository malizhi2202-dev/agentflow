# ③ 结论与建议 · S14 Agent 创建链路（第5轮 2026-09-23）

> 状态：待审⑤ · 依据 `RECON.md` F-1…F-12 + 竞品表 · **未过 ⑤ 人审门前不进 ROADMAP、不得被立项引用**（R16.7）· 全部为文档/原型层建议（零代码改动，裁定⑧）

## 先说一个前置判断

**向导不是第一步，写入路径才是。** 依据：F-5（`frontend/src/pages/AgentDetail.tsx:262/266/270` 采的 system_prompt/role_def/sop 后端无列、PUT 白名单 `backend/routes/agents_api.py:84` 也不收 → 运行期回落 `backend/services/chat_service.py:94` 用 description 当 system prompt）与 F-6（gate 三字段 + visibility + workflow_ids 无任何写入路径）。**先把字段管道接通，再谈几步向导**——否则新向导只是把「填了不生效」重新包装一遍。

## 推荐方向（3 条，按落地次序）

### 方向一 · 「修管道」：最小必填集收敛 + 凭据外置 + 字段全可写（治 F-3/F-4/F-5/F-6/F-9）

1. **最小必填集 = 2 项**：`name` + 一个可跑的模型档位引用；其余 22 字段全部有默认或可空（事实：24 字段里只有 `name` 真阻塞，且缺名现在返 500 而非 400，`agents_api.py:43/54`）。要求：入口层补 Pydantic schema，把「裸 dict 直建」变「契约校验后建」（与 CLAUDE.md「路由只做参数校验与鉴权」一致）。
2. **api_key 从创建流彻底移出**，改为工作区/域级**模型档位（Model Profile）**，Agent 只存引用〔2026-10-15 裁撤：由运行时发现（外部 CLI）取代——模型目录由运行时暴露，凭据留运行时 CLI 机器〕；创建期反馈改成正向的「连通性试跑」。竞品锚：Dify 的 Integrations→Model Provider + Default Models（凭据与默认模型属工作空间，不属单 App）；OpenAI 把 Vaults 列为独立于 Agent 配置的凭据面。事实锚：F-4 `agents_api.py:45` 用字面量 `"not_set"` 占位、F-9 `domain_api.py:243` 副本直接共用同一密文（不可独立轮换）。过渡纪律：现存 `api_key_encrypted` 列保留但降级为「档位未解析时的兜底」，新建一律走引用。
3. **补全写入路径**（同批）：`system_prompt`/`role_def`/`sop`、`gate_pre_check`/`gate_post_check`/`io_filter`、`visibility`、`workflow_ids` 六组字段在创建与更新口都可写；顺手统一前端字段名 `gate_pre`/`gate_post` 与后端列名（F-6）。**这是任何创建形态的地基，不依赖解冻以外的新组件。**

### 方向二 · 「三入口一草稿」：空白快建 / 模板实例化 / 复制既有（+ 导入 YAML 复用编排 apply）（治 F-1/F-10/F-11/F-12）

1. **入口收敛为 3 + 1**：三个 UI 入口（空白、模板、复制）+ 一个非 UI 入口（YAML/DSL 导入）。全部产出同一个「Agent 草稿」对象，进同一份表单继续完善。竞品锚：Dify「Create from Blank + 先定形态」、DSL 直接建 App；Coze「复制感兴趣智能体并改造」。
2. **草稿态**：`status=draft`，不进正式列表、不计配额、不参与调度；「保存并测试」才转 `testing`。事实锚：F-7 现在一 POST 就等同正式 Agent 且删除即物理删（`agents_api.py:101-113`）。
3. **模板落到服务端**：把 `RoleMarket.tsx:20-33` 硬编码的 12 个角色模板迁为服务端模板数据（事实锚 F-12：`roles_custom_api.py:12-13` 现返空 + note 自认硬编码），并补真正的 **角色 → Agent 实例化装配口**（现在是断链：F-10 `CustomRole` 只被 `assembly_api.py` 读去绑工作流节点，Agent 侧零引用、无 `role_id` 血缘字段）。实例化= 一次性快照 + 记血缘（`role_id`/`based_on`），复制后可改。
4. **复制既有 Agent**：把 `domain_api.py:231-249` 已验证可用的「以既有 Agent 为模板造副本」逻辑抽成用户入口，并修两处偏差：不共用密钥密文（方向一第 2 条落地后自然消解）、不继承 `total_tokens_used`/`project_count` 等运行累计量。
5. **导入 YAML 只做半件事不行**：F-11 现状是编排 YAML 里 `agents[i].spec.sop.trigger` 已校验（`orchestration_parser.py:90-93`）但只成画布节点、全仓无 `Agent(` 物化点。建议与 S9 声明式面合并立项：Agent 作为一个 kind，`apply` 即创建（走同一草稿→测试→发布门）。

### 方向三 · 生命周期与归属：5 态状态机 + 发布门 + 归档 + owner 规则（治 F-7/F-8）

1. **显式状态机**：`draft → testing → published → running → archived`，与现存值合流：`standby` 并入 published（已发布待触发）、`paused` 给标签或并档（F-7：`reconcile_loop.py:419` 写 paused 但前端 `AgentBuilder.tsx:35` 无标签）、`completed/error/disabled` 三个前端标签现无生产路径 → 要么由探针/调和写入要么删标签。
2. **规则写在状态转换层**（动作者类型 × 目标状态），不只写提示词——CLAUDE.md 明文约定。具体：谁能建（默认全部登录用户）、谁能发布（发布这一步默认需人批，对齐既有审批面 `ApprovalPage.tsx`）、running→published 的回退谁可执行。
3. **归属**：`owner_id` 建后不可变（现状即如此，`agents_api.py:54`）+ 补显式转让口（当前无任何转让/共主路径）；admin 的跨 owner 读写（`_filter_owner:18-21`）保留但**必须落审计**（现仅 `agent.create/update/delete` 三类，`:58`）。
4. **共享档如实标注**：`visibility` 三档 private/domain/public 只做**可见性过滤**，UI 与文档同步声明「Domain 非安全边界（仅 4 字段逻辑分组，Agent 在平台进程内执行、无沙箱）」——引 CLAUDE.md 现状表原话，避免共享档被误读成租户隔离。
5. **归档代替物理删**：`archived` 可恢复可追溯，物理删仅 admin + 二次确认（保留 running 拒删 `agents_api.py:108-109`）。

### 一句话落地路径

**先补字段管道与模型档位（方向一，纯入口层，半天级可拆），再把「创建 Agent」从单按钮改成三入口产出 draft，最后立状态机与发布门（方向三，需与审批面/指标面联动）。**

## ③ 打磨：预演失败（Pre-mortem）——「一年后回看，这个创建链路失败了」

| 剧本 | 触发链 | 本轮已写入的缓解 |
|---|---|---|
| **1 向导膨胀**：新向导把 22 个可空字段全铺进去，用户 3 分钟建不出来，回流到「直接调 API 的工程师专属」，通用平台定位失守 | F-2 字段数 + 无预算 | 方向二入口收敛 + 必填集 =2 + 硬预算（≤3 步 / ≤5 字段 / 可跳过 ≥60%），并进 ④ 议题门的验收项 |
| **2 假创建**：向导能填但存不下——人格/闸门/共享三组字段静默丢失，用户以为配了权限与护栏，实际跑的是全局默认 | F-5/F-6 无写入路径 + `gate_resolver.py:4` 全局回落 | **方向一排在方向二之前**（前置判断），且要求「向导每字段=一个可写列 + 一条测试用例」；未接通前禁止上线对应表单项 |
| **3 凭据债**：api_key 挪成档位后，存量 Agent 仍带 `"not_set"` 密文与副本共用密文，运行期随机失败，排查面爆炸 | F-4 `or "not_set"` + F-9 `domain_api.py:243` | 迁移期显式化：列出「无有效凭据」清单（可计量数据按裁定⑦ 入 MySQL 表，不再新增文件态）+ 创建/发布期跑连通性试跑作为 testing→published 的门条件 |

红队补充（第一性质疑）：**「创建」与「装配」是不是同一个动作？** 现状是两份同构字段（Agent `models/agent.py:30-33` 与 CustomRole `models/role_custom.py:24-27` 都各有 gate 三字段 + visibility），说明平台在两处重复建模同一护栏语义。结论应明写：**护栏归属 Agent（受管对象），角色模板只携带默认值**，否则方向二的装配口会变成第二条写入路径，F-6 复发。
