## 一 · 四型语义档位（每个资源问「Agent 死了它怎么办」）
| 档位 | 语义 | 删除 Agent 时 | 例 |
|---|---|---|---|
| **owned 拥有** | 生命周期绑死，离了 Agent 无意义 | 级联删或随归档封存（显式二选一，禁默认） | 记忆 · 探针 · 定时任务 · 审批记录 |
| **mounted 挂载** | 装备，可挂可解，本体归别人 | 解挂，本体不动 | 技能 · 知识源挂载关系 · 渠道绑定 |
| **shared 共享引用** | 借看，多对多，零独占 | 只删引用行 | 工具引用 · 模型档位 · 工作流/编排引用 · 公共知识库 |
| **quota/gate 约束与闸门** | 不是资源是规则 | 随 Agent 归档失效 | token 配额 · 发布门 · io_filter |

## 二 · 存储裁定三条（对齐裁定⑦ MySQL 档）
1. **owned → 真外键 + 显式 ondelete**（CASCADE/SET NULL/RESTRICT 必须写面，禁裸 String 默认行为）。
2. **shared → JSON 指针或连接表，不强扭**：`metrics.py:13`、`orchestration.py:22` 既成 JSON 范式保留（引用型无需 DB 级完整性；跨类查询走应用层）。
3. **补债两件（解冻首批小手术）**：`human_approval` 补 FK；knowledge 挂载沿用 `knowledge_tag` 连接表范式。Trigger 关联只记引用字段——现行调度=进程内存（单副本已知缺陷），不归表等执行隔离议题。
